## 사용과 변경 범위

실제 훈련의 가방에 IFAK1개와 의료 물품6종을 넣었다. 한 번 눌러 선택/정보 확인,350ms 안에 두 번 눌러 창을 연다. 제목을 끌어 옮기고 X로 닫는다. 위치와 내용물/배치는 같은 실행에서 기억한다. 비모달 창 하나만 열리며 뒤의3열과 탭을 계속 조작할 수 있다. 창 안과 가방의 물품은 원래 InventoryUI 선택·7px 드래그·destination/drop/run→Inventory.move 경로를 쓴다. 의료 아이템의 탭은 정보 확인이며, 빈 칸 배치와 드래그는 기존 경로다. 처치·시간·효과/controlFactor 연결은 없다.

의료 탭에서 의료 물품/IFAK을 은은하게 강조한다. 선택 정보에는 이름/설명/대상/무게/남은 개수가 있다. 흉부 씰은1세트의2개를2/2로 표시한다. 원본 가방6×5는 그대로다. 초기 탄약/탄창과 총기·조준경 동작도 보존한다. 단위 모델 Inventory에는 includeMedical 옵션을 두고 실제 앱에서 켜며, 기존2D나 다른 도구의 초기 가방을 자동 변경하지 않는다.

왼쪽 장비 화면은 P01의6B47/6B45·앞뒤Granit Br4·소프트 구성을 읽기 전용으로 표시한다. 전술조끼·벨트·배낭은 빈 자리다. 아래 M4/AK 두 카드는 고정 위치에서 탄창/탄 수/조준경과 사용 버튼을 보여준다. 장착/분리는 해당 총을 사용 상태로 고른 뒤 원래 메뉴/드래그를 쓴다. 디버그3번 카드는 몸속 판정 디버그를 켰을 때만 작게 보인다. 의료 탭에서는 신체 아래의 ‘장착 장비’를 펼친다. 두 화면의 가로 잘림은 없으며 세로는 각 열의 독립 스크롤을 사용한다.

총기·광학 무게와 내용물 포함 의료 무게를 아래 소계로 표시한다. 전체 방호/탄약까지 합친 군장 총질량으로 표시한 것은 아니다. D2의13.7kg 장비 입력은 이번에 연결하지 않았다. 두 탭에서 게임 시간은 흐르고, 일시정지와 쓰러진 뒤 의료는 정지하는 M1 정책을 유지한다.

## 구성과 격자 조정 보고

미 육군 CALL17-13 TCCC Handbook2017 표3-2에서 IFAK II의 NPA를 확인했다. 실제 Army 목록은 CAT2개와 거즈/탄력붕대·테이프·장갑·씰·안대·절단기·마커 등을 포함하고, Army IFAK II에 감압 바늘은 없다. 인접 WALK 목록에는14G 감압 키트가 있다. 사용자 설계에 따라 CAT1/QuikClot1/NAR ETD4인치1/HyFin통기형 씰2개1세트/ARS14G1/NPA28F1로 넣었다. 장갑·테이프는 제외했다. 실제 Army 지급 키트 전체 재현은 아니다.

제조사 포장 치수/무게를 사용하고90mm 명목 격자로 긴 축을 세로로 배치했다. CAT·붕대·바늘·NPA는1×2씩, 거즈·씰은2×2씩으로 총16칸이다. 요청의 임시3×3에는 들어가지 않아 사전에 보고하고 **내부4×4**로 바꿨다. **외부2×2는 사용자 지정 그대로**다. 내부 격자는 정리 공간의 추상화이고 파우치를 실제로 펼친 면적/부피가 아니다. 배치와 제품별 원수치/출처는 대장과 보고 표에 있다.

IFAK 파우치는 TT TAC IFAK POUCH M의 공표159g을 사용했다. 현재 제조사 페이지190×130×64mm와 구형2024 카탈로그180×125×65mm가 달라 현재 제품 페이지를 택했다. 외부2×2는 이 물리 치수의 단순 반올림이 아닌 사용자 지정값이다. 내용물248.058g+파우치159g=407.058g이며 이동 중에도 중복 합산하지 않는다.

## 소유권과 입력

medicalSupply와 medicalContainer를3D에 추가했다. 물품은 한 Map에 한 instanceId/owner만 가진다. 내용물 owner는 container:ifak-01이다. rootOwner는 무기/컨테이너 부모를 재귀 탐색하고 방문 집합으로 순환/자기/없는 부모/잘못된 부모 종류를 차단한다. IFAK에는 medicalSupply만 가능하고 컨테이너 중첩은 거부한다. 열린 IFAK의 동적 layout과 접근 권한을 원래 Inventory 경로에 연결했다. 부모를 옮기면 자식 소유자는 유지되고 최종 소유자만 따라간다. 가방/파우치 사이 이동·300회 왕복·수량/질량/탄약 보존을 검증했다.

창 제목의 포인터 소유권은 아이템 드래그와 별개다. 창을 닫는 중 내부 아이템을 잡고 있었다면 원래 endGesture로 취소해 분실을 막는다. 창 크기264/220px, 내부 표시 셀52/44px, 안전 여백8px, 닫기44px는 UI 튜닝이다.

실제 오프라인 Chromium에서 드래그 후 닫기 터치에 브라우저 합성 click이 누락되는 것을 재현했다. 공통 UI 버튼/summary/신체 선택을 터치·펜 pointerup에서 기존 click 명령으로 활성화하고700ms 이내의 뒤따르는 호환 클릭만 억제한다.7px 이상 이동/취소에는 실행하지 않는다. 마우스/키보드는 원래 경로다. 격자/장비 아이템은 이 처리에서 제외하므로 **원래 아이템 down/up/drop/run 엔진은 바이트 보존**한다. 원래 이동·사격·조준 터치 소유권은 바꾸지 않았다.

## 출혈 방향과 구획

B1의 source.rawFlow/flow/cumulativeMl·총 loss 누적·bloodMl 감소 연산은 그대로다. 원래 pool 누적 한 지점만 routeLimbVolume으로 연결했다. 혈관 출혈원(artery/vein)이 limb_compartment로 갈 때, 각 실제 lesion의 현재 면적 비율로 나누고 M1의 검증된 피부 입출구를 사용한다.

| 상태 | 초기 외부/구획 비율 |
|---|---:|
| 입구와 출구 |85/15%|
| 입구만 |40/60%|

비율은 튜닝이다. 입출구의 면적을 실측해 반영하지는 않았다. 기존 source.position의 부위/뼈 이름으로 좌우 상완/전완/허벅지/아래다리를 구분한다. 구획 용량1250/750/500/250mL,50% 충만 뒤 내부 비율 선형 감소,75%부터 ‘단단하게 부어오름’은 모두 튜닝이다. 넘는 몫은 확인된 열린 통로로 밖에 보낸다. 압력 지표는0–1 표시 프록시이며 mmHg가 아니고 출혈 유량·통증·기능/순환으로 역입력하지 않는다. 구획 증후군 효과는 없다.

대퇴골 골절에서 최대1.5L라는 교범 자료 등은 출혈량 참고치이며 구획 용량의 실측값이 아니다. 전완250mL는 적절한 공개 근거를 확인하지 못해 순수 튜닝이다. 다른 선택값도 실측 용량이라고 제시하지 않았다. 피부 진입을 확인할 수 없는 기록에는 통로를 만들어내지 않고 기존 내부 분배를 유지한다. **미확인/닫힌 기록의 용량 제한은 이번 성공 범위에 포함하지 않는다.** 유량 고정 상태에서 닫힌 공간의 초과 혈액을 처리하는 별도 설계가 필요하며, 실제7사례의 대상 사지 혈관은 모두 피부 통로를 확인했다.

추가 자료는 의료 객체 키의 WeakMap이다. TrainingMedical.limbRouting getter가 부위별 volume/fullness/pressure와 sourceId별 external/internal 분배 및 lesion 정보를 복사해 제공한다. 의료 본체의 변경 필드는 bloodPoolsMl뿐이다. M1 관찰은 이 외부 분배를 읽어 대퇴동맥 관통상을 ‘뿜음’으로 보여준다. 몸통 목적지는 그대로다.

원래 destination 및 external/internal 호환 요약은 기존 임상 계산 입력으로 남겼다. 실제 분배의 관찰이나 이후 M3는 sourceId와 limbRouting.sources/segments를 사용한다. 디버그에는 실제 분배/구획량/충만도와 호환 요약의 의미를 함께 표시한다. 처치가 여기에 연결된 것은 아니다.
