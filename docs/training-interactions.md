# v14 근접 상호작용과 입력

상자 버튼을 화면 **중심에서 조금 오른쪽**에 작게 배치한다. 병사 H01 근처에서는 같은 버튼이 의료 상태 진입으로 바뀐다. PC 상호작용은 F이며 E는 사용하지 않는다.

## 사용

- 상자에 다가가 `탄약상자 / 열기`를 터치하거나 F를 누르면 기존 파밍 인벤토리가 열린다.
- H01에 다가가 `H01 / 의료 상태`를 터치하거나 F를 누르면 기존 H01 의료 기록을 펼치고 해당 위치로 스크롤한다. 이 화면에서는 시간이 멈춘다. `훈련으로 돌아가기`로 이어서 플레이한다.
- 설정의 `PC 우클릭 조준`에서 **토글** 또는 **누르는 동안 유지**를 선택한다. 기존 동작인 토글이 기본값이다. 설정을 저장하며 이전 저장값은 토글로 불러온다. 카메라 프리셋은 이 선택을 유지하고 설정 초기화는 토글로 되돌린다.
- 터치 조준 버튼과 Q는 두 방식 모두 토글이다. 유지 방식의 우클릭은 버튼을 떼거나 훈련을 일시정지하면 해제한다. 좌우 마우스 버튼을 함께 누를 때 사격과 조준 해제를 각각 처리한다.
- 이동 패드를 계속 누른 채 장전·조준·앉기·사격 버튼을 누를 수 있다. 이동+시점+별도 동작의 세 손가락 입력도 각각 관리한다. 인벤토리나 메뉴로 진입할 때는 기존처럼 입력을 비운다.

## 배치와 근접 판정

공유 버튼은 기존 `lootButton` ID를 유지하고 `data-command="interact"`를 사용한다. 중심 X는 `50% + clamp(62px, 9vw, 108px)`, 중심 Y는 화면 높이의48%다. 최소 너비90px·높이44px, 제목11px·동작10px로 줄였다. 오른쪽 화면 가장자리로 옮기지 않는다. 작은 가로화면의 터치 영역은44px를 유지한다. PC에는 F 키 표시가 보이고 터치 화면에서는 숨긴다.

상자는 기존2.1m·차폐 검사를 유지한다. H01도 수평거리2.1m와 눈→몸통의 차폐 검사를 적용한다. 대상이 멀거나 가려지면 표시하지 않는다. 두 종류가 동시에 가능하면 가까운 대상을 선택한다. 인벤토리·메뉴에서는 버튼을 숨기며, 실제 실행 시에도 근접 가능 여부를 다시 검사한다. H01은 계속 A 자세로 고정한다.

## 터치 처리

훈련 HUD 동작 버튼은 touch/pen의 `pointerdown`에서 한 번 실행하고 호환 `click`은 걸러낸다. 두 번째 손가락은 브라우저가 click을 만들지 않는 경우가 있어 기존 click 전용 방식으로는 실행을 보장할 수 없었다. 버튼을 누를 때 다른 pointer 소유권을 지우지 않는다. HUD 버튼에는 `touch-action:none`을 적용한다. 이동 소유자는 한 명으로 제한하고 이동·시점·사격은 pointer ID별로 해제한다. 버튼을 떼거나 다른 손가락을 취소해도 살아 있는 이동 입력을 유지한다.

`scripts/check-training-interactions.mjs`는 배포 HTML의 바이트 그대로를 오프라인 Chromium에 공급한다. 앱 상태를 변경하는 시험 API나 순간이동을 추가하지 않는다. 실제 RAF·키보드·마우스·CDP 다중 터치로 이동·버튼·모달을 검증한다. 근접 지점 이동은 두 화면 모두 실제 WASD 입력을 쓰므로 모바일의 장거리 이동을 터치로 검사했다는 뜻은 아니다. 동시 조작은 실제 CDP 다중 터치로 검사한다. CDP의 부분 touchEnd에는 **떼는 손가락의 ID**를 전달한다. 테스트 코드·QA 번들은 HTML에 넣지 않는다.

## 계산 경계

이번 변경은 HUD·근접 의료 진입·입력·조준 방식 저장에 한정한다. 조준 수식·카메라/렌즈/반동·fixed tick·관통/방호·인체 저항·원본 의료 계산·H01 모델/리그/피격체는 수정하지 않는다. v13의 의료·스킨·관통 검증은 해당 버전의 증거이고 이번 HTML의 새로운 전체 재검증으로 표현하지 않는다. 치료 기능을 추가한 것은 아니다.

검증 결과와 실제 HTML SHA는 [v14 검증 기록](../downloads/verification-interactions-v14.json)을 따른다. 실제 Android/iOS 기기 조작감·파일 열기는 후속 기기 검증 대상이다.
