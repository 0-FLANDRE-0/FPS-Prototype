# 3D 장애물 관통 시험장

원본 CQB의 장애물 탄도 계산을 3D 훈련장에 연결했다. 방탄복·플레이트·인체 피해 계산은 다음 단계다.

## 원본 계산과 3D 경계

`scripts/training-ballistics.mjs`는 필요한 선언만 읽어 `apps/training/src/generated/legacy-ballistics.js`를 만든다. 함수 본문과 계수는 변경하지 않는다. 생성 모듈과 빌드 정보에 원본 파일 해시·선언 목록을 기록한다. 생성 파일을 직접 편집하지 않는다.

| 원본 | 재사용하는 계산 |
| --- | --- |
| `src/runtime/scale.js` | 원본 32 px/m 변환 |
| `src/runtime/game-state.js` | 재질별 m당 저항, 실제 통과 길이의 유효 저항, 재질별 손실 |
| `src/data/ammunition-legacy.js` | 에너지 등급·탄자 성격·조합별 손실 배율 |
| `src/combat/armor-resolution.js` | 원본 `penetrationProbability` 함수만 추출 |
| `src/combat/ballistics.js` | 탄종 장벽 특성, 도탄 확률·감쇠·방향 분산, 누적 손실, 안정성에 따른 관통 후 흔들림, 탄자 소진·절대 차단 기준 |

원본 `CQB_Tactical.html`과 2D `src/`는 수정하지 않았다. 전체 스크립트를 wrapper로 감싸거나 전체 방호·의료 경로를 복제하지 않고 실행에 필요한 좁은 선언만 격리한다.

`apps/training/src/ballistics.js`는 3D 공간 어댑터다. Rapier에서 가장 가까운 충돌을 찾고, 박스의 실제 진입·출구 사이 거리를 m로 구한다. 원본 함수에 넘길 때만 px로 변환한다. 비스듬한 사격·측면 모서리·박스 안에서 시작하는 광선도 실제 통과 길이를 사용한다. 모서리를 무한히 두껍게 처리하는 `두께 / cos(각도)` 근사만 사용하지 않는다.

초기 관통력·피해 지표·장벽 배율은 원본 최종 `AMMO_PRESETS`에서, 속도는 기존 M4 총열 resolver에서 가져온다. 원본 확률 관통에 실패하면 도탄을 판정하고, 성공하면 원본 탄속·관통력·피해·안정성 감쇠를 적용한다. 다음 장애물은 잔여 상태를 이어받는다. 안정성이 소진된 탄은 뒤 표적에 적중 처리하지 않는다. 안전 상한은 원본과 같은 16개 segment다.

원본의 관통 후 signed angle과 도탄 반사·분산 각도는 3D 입사 평면으로 옮긴다. 난수는 확정 발사 번호별로 격리하여 렌더·효과가 결과를 바꾸지 않는다. 원본 게임 밸런스와 확률을 유지하며 실측 방탄 시험이나 새로운 물리 관통 모델로 표현하지 않는다. 현재 탄은 사건 단위의 즉시 광선이며 중력 낙하·비행 시간·추가 공기저항 계산을 이번 단계에서 도입하지 않는다.

## 시험장

바닥을 기존 18×26m에서 40×40m로 확장했다. 기존 표적·엄폐·탄약상자·시작 위치를 유지하고 오른쪽 통로로 SECTOR 02에 진입한다. 노란 바닥 경로와 표지판을 따른다. 레인 사격선에서 뒤 표적까지 12m다.

| 번호 | 재질 | 공칭 두께 |
| --- | --- | --- |
| 04 | 드라이월 | 12cm |
| 05 | 목재 | 30cm |
| 06 | 유리 | 8cm |
| 07 | 금속 (`thin_metal`) | 24cm |
| 08 | 콘크리트 | 50cm |
| 09 | 강철 | 32cm |
| 10 | 두꺼운 목재 | 100cm |
| 11 | 다층 목재 | 20cm × 3겹, 층 사이 빈 공간 |

두께는 실제 3D 충돌 형상의 크기다. 저항은 원본 CQB의 m당 게임 계수다. 재질명·cm 표시를 현실의 방호 성능이나 인증과 동일시하지 않는다. 기존 12개 호환 탄종으로 탄창을 만들어 비교한다. 약실에 이미 든 탄을 보존하는 기존 장전 규칙은 유지한다.

유리는 투명하게, 목재·금속·석재는 각 표면으로 표시한다. 진입·출구 자국과 재질별 색의 입자 효과, 뒤 표적 자국을 구분한다. 자국이 실제 구멍을 뚫거나 장애물을 파괴하지는 않는다. 반복 사격 후에도 저항과 캐릭터 충돌을 유지한다.

화면은 관통·정지·도탄·탄자 소실을 보여준다. 정지한 탄의 속도·에너지는 **충돌 순간**의 값이며 장애물을 뚫고 나간 값이 아니다. 관통 후 수치는 원본 손실을 적용한 잔여 상태다. 원본 damage는 잔여 지표로만 추적하고 표적의 생리·상처는 계산하지 않는다. 장애물 뒤 표적까지 도달한 한 발을 한 번만 센다.

## 탄 궤적 표시

일시정지 → **조작·화면·훈련 설정 → 탄 궤적 표시**를 켠다. 기본은 꺼짐이며 설정을 저장한다. 실제 총구부터 판정된 접촉·진입·출구·최종 탄착까지 이어지는 경로를 장애물 너머까지 표시한다. 일반 구간은 연노랑, 관통한 뒤는 하늘색, 도탄한 뒤는 분홍색이다. 다음 상호작용이 일어나면 해당 지점부터 색이 바뀐다. 관통한 장애물 내부의 실제 통과 구간도 하늘색으로 잇고, 정지·소진 지점에서 경로를 끝낸다.

원본의 안정성 감쇠와 signed wobble이 계산한 관통 후 방향을 그대로 그린다. 화면에 새 산포나 탄도 난수를 추가하지 않는다. 탄자 자체의 회전·텀블링을 그리는 기능이나 비행 시간을 가진 예광탄은 아니다. 발사 판정 후 남는 훈련용 경로 표시다.

최근 **활성 훈련 시간 5초·최대 24발**을 유지한다. 일시정지 때 수명도 멈추고, 인벤토리를 열었을 때는 계속 줄어든다. 표시를 끄거나 훈련을 초기화하면 남은 선을 즉시 지운다. 설정 초기화는 표시를 끄며 카메라 프리셋 변경은 선택을 유지한다. 고정된 instanced mesh 한 개를 재사용하여 자동사격 때 객체·GPU 버퍼가 계속 늘어나지 않게 한다. 궤적 색 범례는 표시를 켰을 때 HUD에 나타난다.

## 검증

```sh
npm test
npm run verify:baseline
npm run build:training
CQB_BROWSER_EXECUTABLE=/usr/bin/chromium npm run test:training:penetration
CQB_BROWSER_EXECUTABLE=/usr/bin/chromium npm run test:training:trajectories
CQB_TRAINING_FOCUS=tuning CQB_BROWSER_EXECUTABLE=/usr/bin/chromium npm run test:training:browser
```

`tests/training-ballistics.test.mjs`는 원본 VM과 추출 모듈을 12개 탄종×6개 재질 fixture로 대조한다. 통과 길이·관통/도탄 확률·손실 배율·잔여 상태·흔들림이 원본과 같아야 한다. Rapier 통합 검증은 직격·후방 표적·두께/입사각·모서리·다층 누적·AP/파쇄탄·도탄·총구 차폐·절대 차단을 확인한다.

`scripts/check-penetration.mjs`는 읽기 전용 snapshot과 입력 이벤트로 모바일 두 해상도·PC에서 기존 표적 → 오른쪽 통로 → 드라이월 관통/후방 적중 → 콘크리트 정지/후방 미적중 → 플레이어 충돌을 검증한다. 결과·빌드 해시·스크린샷은 Git 제외 `artifacts/penetration/`에 기록한다. 실제 Android/iPhone의 성능·발열·조작감은 별도 확인이 필요하다.

궤적 모드는 같은 실제 이동·사격 경로에 설정 기본값·저장/복원·구간별 색·자연 도탄·수명·끄기/초기화를 추가하며 `artifacts/trajectories/`에 기록한다. `tests/training-trajectories.test.mjs`는 실제 관통/도탄 구간과 GPU 인스턴스의 양 끝·색을 대조하고, 표시가 판정 상태를 바꾸지 않는지와 기록 상한·삭제·자원 해제를 확인한다.
