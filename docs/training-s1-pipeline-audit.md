# S1 파이프라인 조사와 몸속 조회 계약

조사 기준: v38 `5f1236aa84c9a9a5da5a907ec7a7b417aac223de`. 확인일: 2026-10-16(한국). 이 문서는 기존 경로 조사와 S1용 조회 캐시를 설명한다. 의료 배율·출혈 계수의 최종값과 보정 결과는 S1 대장과 결과 보고서가 우선한다.

## 기존 속도와 에너지 경로

`traceShot()`은 비행·장벽·방호·인체를 하나의 탄 상태 `s`로 순서대로 처리한다. 비행에서 갱신한 `s.velocity`를 방호가 받으며, 방호를 통과한 뒤 동일한 `s.velocity`를 `resolveBodyPath()`가 받는다. 방호 뒤에 탄속을 탄약 프리셋이나 총구 속도로 되돌리는 단계는 없다.

| 값 | v38 생성 위치와 의미 | S1에서의 사용 |
| --- | --- | --- |
| `body.velocityInMps` | `protection.resolveBodyPath()` 진입 직전 `snapshotResidual(s).velocityMps` | 방호가 남긴 실제 입사속도의 증거 |
| `body.velocityOutMps` | 같은 함수의 기존 인체 저항·최종 잔여 관통력 비율 계산 | 실제 비행에 계속 쓰는 출구속도. S1은 교체하지 않음 |
| `part.energyShareJ` | 인체 전체 에너지 손실을 실제 통과한 부위별 저항 비용에 비례하여 배분. 마지막 부위는 나머지를 받아 합계 보존 | 기존 부위별 에너지 증거 |
| `part.velocityInMps` | `sqrt(2 × (body.energyInJ − 앞 부위까지 배분한 에너지) / massKg)` | 각 부위의 S1 계산 시작속도 |
| 부위 출구속도 | 별도 필드는 없음. `sqrt(max(0, part.velocityInMps² − 2 × part.energyShareJ / massKg))`로 읽을 수 있음 | 다음 부위 입사속도와 비교하는 감사값 |
| `part.damageIn` | 기존 입사 데미지에서 앞 부위의 관통 비용을 차감한 관통력 비율 | 이 값에 기존 의료 조직손상 배율과 S1 `m`을 적용 |
| `part.entryDistance/exitDistance` | 실제 점유 인체 셀을 잘라 합친 해당 부위만의 구간 | 해당 구간만으로 부위의 유효 손상량과 `m`을 계산 |

인체 통과 후 속도는 사람별 최초 입사값(`personEntry`)에 고정하여 계산하므로, 팔과 몸통을 하나의 경로로 처리하거나 분리된 연속 경로로 처리해도 인체 출구 결과가 중복 감쇠되지 않는다. `incomplete_body_path`는 계산 범위 안에서 출구를 보지 못한 경우이므로 `energyAccountingComplete:false`이며, 기존 속도를 유지한다. 새 모델이 추정한 정지 깊이나 출구속도가 이 결과를 덮어쓰면 안 된다.

S1 모델의 계산용 속도·질량·yaw·파편은 별도 상태이다. 다음 부위 계산은 **기존 `part.velocityInMps`**에서 시작해야 하며, 앞 부위의 새 모델 출구속도로 대체해서는 안 된다. 부위 사이의 yaw·질량을 이어 쓰는 경우에도 실제 비행 상태를 변경하지 않는다는 계약은 같다. 구간 사이의 공기 틈을 조직 깊이로 더해서는 안 된다.

## 방호가 넘기는 정보와 넘기지 않는 정보

`resolveArmorBatch()`는 원본 방호 결과를 3D 상태로 연결한다. 원본 패킷은 출구속도를 직접 보고하지 않는다. 기존 3D `setResidual()` 어댑터가 남은 관통력의 비율로 `velocity *= sqrt(ratio)`와 `damage *= ratio`를 적용한다. 이 어댑터의 결과가 인체 입사속도이다.

| 필드 | 의미 | S1 해석 제한 |
| --- | --- | --- |
| `armorResults[].before/after.velocityMps` | 방호 전후 기존 3D 속도 | 잔여속도를 그대로 사용 |
| `residualThreatPacket.residualIntegrity` | 관통자의 원형 유지 정도에 대한 원본 0–1 모델 | 수치적인 탄두 형상이나 yaw는 아님 |
| `residualBreakup` | 원형 훼손의 원본 보조값 | 실제 파편 질량·개수·분포는 아님 |
| `residualKind` | `intact_penetrator`, `deformed_core`, `fragmented_core`, `spall_fragment` 등 원본 분류 | 변형·파편 분류의 전달은 있음. S1 초기 형상으로 반영하지 않음 |
| `s.stability`, `body.before.stability` | 원본 관통·도탄 안정성/원형 유지 보조 상태 | `yawRad`로 변환하지 않음 |
| `armorResults[].wobbleDeg` | 방호 통과 뒤 탄의 **진행 방향** 변화 | 탄 축과 진행 방향 사이의 yaw가 아님 |
| 특수 sabot 패킷의 `residualYawRisk`, `residualDeflectionRisk`, `residualMassPenalty` | 일부 원본 특수탄에만 있는 위험/질량 분류용 보조값 | 확정 초기 yaw나 실제 잔여 질량이 아님 |
| `wear.backfaceDeformationHint` 및 방호구 변형 모드 | 방호구 자체 손상·후면 변형 | 탄두 변형으로 오인하지 않음 |

`TrainingMedical.record()`는 앞선 방호 결과를 `trainingMetadata.armorHistory`에 복사하고 `impactPacket.residualIntegrity`도 전달한다. 따라서 분류·안정성·방호 이력은 의료 기록에 도달한다. 그러나 v38에는 일반 탄의 수치적인 방호 후 yaw, 변형 직경·길이, 실제 파편별 질량을 전달하는 인터페이스가 없다. S1은 요청대로 초기 yaw와 변형을 방호 정보에서 만들지 않는다. 이미 방호가 바꾼 진행 방향은 실제 궤적에 그대로 남는다.

## 1회 3D 조회와 1D 진행의 분리

기존 `physics.annotateInternal()`은 `traceShot()` 완료 후 실제 점유 인체 경로마다 `intersectInternalBody()`를 한 번 호출한다. 셀마다 3D 조회를 하는 경로는 없다. 한 발이 서로 분리된 인체 경로를 여러 번 만나면 이 기존 호출도 경로 수만큼 발생한다.

원래 `internalHits`는 탄 반지름으로 확장한 직접 교차이고, `nearMisses`는 직접 교차하지 않은 비뼈 구조 중 **2 cm 이하**만 담는다. 이 범위는 최대 15 cm인 S1 순간 공동·파편 조회 범위보다 짧다. 2 cm 결과만 사용하면 장기 손상을 누락한다.

S1은 같은 `internalWorldShapes()` 순회에서 `cavityCandidates` 배열을 추가한다. 기존 최소거리 탐색 결과를 재사용하고, 최대 0.15 m에 들어오는 깊이 구간의 경계만 추가로 구한다. 기존 `internalHits`와 `nearMisses`의 배열 순서·필드·값은 유지한다. 뼈는 후보에 넣지 않는다.

| 캐시 필드 | 계약 |
| --- | --- |
| 원래 `id/identifier/organ/domain/bone/candidate/vesselKind/cordRegion` | 기존 구조 식별자 유지 |
| `cavityIntervals` | 탄로 중심에서 구조 표면까지 최대 0.15 m인 깊이 구간들의 합집합. 시작·끝은 실제 점유 인체 길이로 잘림 |
| `closestDepthM` | 기존 최소거리 탐색의 깊이. 해당 부위 구간을 선택하는 유일한 기준으로 사용하지 않음 |
| `surfaceDistanceM` | 기존 `distanceM + bulletRadiusM`. **미교차에서** 탄로 중심↔구조 표면 최단거리. 직접 교차에서는 반지름 이하 거리가 보수적으로 반지름으로 기록되므로 직접 교차 구간을 우선 사용 |
| `actualIntersection` | 원래 직접 교차 구간의 존재 여부. 새 공동 손상을 직접 교차로 위장하지 않음 |
| `cavityRadiusMaxM` | 0.15 m. 상처 모델의 반경 상한과 같아야 함 |
| `volumeM3`, `volumeMethod` | 타원체는 `4πabc/3`. 캡슐 체인은 `Σπr²L + 4πrMax³/3`인 연결 관의 합집합 **근사** |
| 혈관 캡슐의 `diameterM`, `diameterSource` | 기존 월드 캡슐들의 최대 반지름 × 2. `fitted original anatomical collider; game tuning, not measured human vessel lumen`로 기록하며, 문헌의 실제 혈관 내경과 구별 |

캡슐 체인의 체적은 분할마다 구를 합산하지 않으므로 12분할에 따른 심한 구 체적 중복을 피한다. 곡선의 안쪽 중복, 다른 반지름의 접합, 분기까지 정확하게 적분한 체적은 아니다. 장기 메쉬를 실측한 해부학적 체적이라고 표시해서는 안 된다.

중요한 구분: 기존 `centerlineDistanceM`은 캡슐이면 혈관 중심축까지의 거리이고 타원체이면 장기 중심까지의 거리라 의미가 같지 않다. 이를 순간 공동 반경과 일괄 비교하면 큰 타원체를 잘못 처리한다. S1 캐시의 표면거리와 깊이 구간을 사용한다. 부위별로 `cavityIntervals`를 자른 뒤 자기 구간의 곡선만 적분하며, `closestDepthM`가 다른 부위에 있다는 이유만으로 후보를 버리지 않는다.

이 캐시는 최대 반경에 대한 보수적 구간과 하나의 최소 표면거리를 제공한다. 장기의 모든 깊이에서 단면 형상을 정확히 재구성한 필드는 아니다. 1D 유효 부피 추정에서 이 근사를 사용한다면 튜닝/근사로 대장에 남겨야 한다. 셀마다 다시 3D 도형을 조회하여 정확도를 가장해서는 안 된다.

## 의료 심각도 연결 지점

현재 원본 생성 모듈에는 `buildPhysiologicInjuryModel()`을 교체하는 슬롯이 없다. 기존 슬롯 중 `buildConfirmedInjuryModel(w, bt, ...)`은 장기·폐·생리 손상이 생성된 다음, 혈관 증거와 최종 출혈 계산 전에 호출된다. 이 지점의 3D 전용 래퍼는 생성 모듈을 수정하지 않고 새 심각도를 적용할 수 있는 최소 연결 지점이다.

주의할 점:

- `physiologicInjuries[].severity`만 바꾸면 원본이 이미 만든 `effects`와 `physiologicEffectProfile`는 변하지 않는다. 실제 의료 tick에 반영하려면 같은 심각도로 효과를 다시 계산·집계해야 한다. `majorVesselMul` 같은 배율은 0이 아닌 **1 기준의 차이**를 처리한다.
- 순간 공동만 닿은 장기에도 기존 손상 타입을 적용할 수 있지만, 실제 탄 교차인 `internalHits`에 가짜 항목을 넣으면 안 된다. 공동·파편 원인과 직접 교차를 기록에서 구별한다.
- 기존 뼈 골절 RNG는 실제 직접 교차만 사용한다. 공동 후보에는 뼈가 없으며 기존 골절 입력을 바꾸지 않는다.
- S0의 뇌·뇌간과 R2의 척수·기도는 실제 교차를 읽는 별도 연동도 있다. 새 공동 손상 기록만 만들어 놓고 이 소비 경로가 읽지 않는 상태를 놓치지 말아야 한다. 직접 뇌 교차의 기존 즉시 무력화 조건도 회귀 검사한다.
- 원본 `applyDamageEvent()`의 HP 감소는 명시적 `ev.tissueDamage`가 있으면 이를 우선한다. `part.damageIn × 기존 ammoMedicalProfile.tissueDamageMul × m`을 넣고 실제 `rawDamage`, 속도, 운동에너지, 관통력 증거를 유지하면 중복 감쇠를 피한다. `m=1`은 기존 HP 감소와 같아야 한다.
- `computeWoundSize()`에는 원본 탄약 데미지를 최솟값으로 읽는 경로가 있다. `rawDamage`만 줄이는 방식은 장기 심각도를 새 부피 모델로 교체했다는 의미가 아니며, 골절·기존 상처 크기에도 의도치 않은 영향을 줄 수 있다.

## 조회 캐시 검증과 비용

`tests/training-internal-s1.test.mjs`는 수정 전 v38 실행 결과를 동결해 직접 관통·접선·2 cm 근접·그보다 먼 경로·체내 정지·미진입 11조건의 기존 두 배열을 모든 필드까지 엄격 비교한다. 추가로 2 cm 밖 장기가 새 캐시에 잡히고 직접/근접 교차로 승격되지 않는지, 뼈 제외, 체적, 점유 길이 clipping을 확인한다. 기존 내부 판정 시험과 함께 **6/6 통과**했다.

같은 Node 프로세스에서 원본 함수를 기준 커밋에서 가져와 동일 형상으로 비교했다. 초기 준비 후 15개 배치, 배치당 10회(합성은 11경로 × 10회) 측정한 값이다. CPU 경합에 따라 절대값은 달라질 수 있으며, 이 표는 새 **1D 상처 모델의 0.1 ms 예산**과 별도인 3D 조회 비용이다.

| 조건 | v38 중앙값 | S1 캐시 추가 중앙값 | 비율 |
| --- | ---: | ---: | ---: |
| 합성 구조 3개(비뼈 2개) | 0.1717 ms | 0.2272 ms | 1.323배 |
| 실제 내부 구조 76개, 흉부 경로 | 16.7815 ms | 19.4934 ms | 1.162배 |

실제 경로는 직접 4개·기존 근접 2개·공동 후보 23개였으며 기존 두 배열은 원본과 엄격 동일했다. 원시 15개 표본과 경로는 `artifacts/s1-internal-audit/query-performance.json`에 있다. 초당 약 200발 부하에서는 기존 최소거리/도형 조회도 별도 병목으로 보고해야 한다. 새 1D 모델만 0.1 ms 안에 들어와도 전체 사격 비용이 그 예산 안에 들어온다는 뜻은 아니다.

## 예산 초과 후 로드 시점 LUT 전환

초기 직접 계산은 서로 다른 실제 피격 입력 1,000개에서 중앙값 0.1130 ms, p95 0.4877 ms로 0.1 ms 예산을 넘었다. 지시서의 조건에 따라 `wound-channel.js`는 발사 전에 **모듈 로드 시점에** 114개 등록 탄 × 두 입사속도 클래스 × 513개 깊이 표본의 테이블을 만든다. 발사 결과를 뒤늦게 캐시하는 방식은 쓰지 않는다.

속도 클래스는 각 탄의 파편화 문턱 미만과 문턱 이상이다. 파편화가 없는 탄은 두 클래스의 응답이 같다. 현재 저항식은 속도 제곱에 비례하고 깊이에 대한 속도 해는 `vOut = vIn × exp(−ρCdAΔx/(2m))`이므로, 단위 입사속도 곡선에 실제 속도와 에너지의 제곱 비례를 적용할 수 있다. 이 관계는 현재 게임 모델의 계산 성질이며 새로운 실측 탄도 법칙이라는 뜻은 아니다.

테이블은 5 mm 간격으로 yaw·투영 면적·전질량/파편화 후 질량의 한 칸 감쇠·파편 에너지 CDF·파편 반경과 두 클래스의 단위 속도/순간 공동 곡선을 준비한다. 실행 중에는 깊이에 따라 값을 선형 보간하고, 각 부위의 **기존 입사속도를 다시 넣은 다음** 보존된 질량·파편 에너지 상태를 진행시킨다. 이 속도 재주입과 부위 경계의 오프셋 때문에 전체 상처 결과를 한 곡선으로 복사하지 않고 표의 응답 계수를 사용한다. 사용자 정의 질량은 기존 표의 감쇠 지수를 질량비로 재환산한다. 실제 비행·방호·인체 출구속도는 바꾸지 않는다.

`WOUND_LUT_INFO`에 로드 방식과 범위가 기록된다. 표의 숫자 배열은 4,678,560 B이며, 예비 측정에서 원본 프로파일 보정이 끝난 뒤 LUT 생성만 약 19.5 ms였다. 배열은 실행 시 생성되므로 ZIP에 이 바이트 수만큼 추가되는 것은 아니다. 표 밖의 깊이는 기존 yaw 마지막 구간이 일정한 성질에 따라 끝값을 사용한다. `computeWoundChannelDirect()`는 같은 공개 입력으로 원래 직접 적분을 실행하는 QA용 비교 함수이다.

함께 적용한 계산 최적화는 다음과 같다.

- 매 셀의 반복 `find`, `map`, 배열 생성, `hypot`를 제거하고 피격 시작에 장기별 직접 교차·후보·축 구간을 캐시한다.
- 현재 곡선의 최대 반경 밖에 있는 공동 전용 후보는 유효 부피가 정확히 0이므로 제외한다. 직접 교차는 이 필터로 제외하지 않는다.
- 셀의 반경보다 표면 거리의 제곱이 큰 공동 후보는 그 셀에서 즉시 건너뛴다.
- 원본 입력·기존 형상·최대 512개 진행 셀·의료 데이터는 단순화하지 않는다.

최적화된 직접 계산과 최적화 전 원본(파일 SHA-256 `a16567c54fed9f2a81173c7b2f4a1f2a92d532295f9968ee40e5c1844a926ecc`)을 같은 1,000개 입력으로 비교했다. 최대 `m` 차이는 `3.33×10⁻¹⁶`, 계산용 출구속도 차이는 0, 장기 심각도 차이는 `8.98×10⁻¹⁵`였고 장기 ID·파편화 차이는 없었다. 따라서 아래 표의 차이는 반복문 최적화가 아니라 LUT 깊이 보간에서 생긴다.

| 비교 항목 | 같은 실제 입력 1,000개의 최대 절대 차이 |
| --- | ---: |
| 부위 배율 `m` | 0.0019476 |
| 새 모델 계산용 출구속도 | 0.6981 m/s |
| 장기 심각도 | 0.018588 |
| 순간 공동 반경 | 1.9783 mm |
| 영구 공동 반경 | 0.2033 mm |
| 파편 범위 반경 | 0.05814 mm |
| 부위 유효 손상 부피 | `4.869×10⁻⁷ m³` |
| 파편화 판정 / 셀 수 차이 | 0 / 0건 |

장기 ID 차이는 3건이었다. 모두 순간 공동의 경계에서 실제 양의 작은 유효 부피가 생기거나 없어지는 경우이며, 부동소수점 0 잡음으로 처리하지 않았다.

| 입력 번호 / 구조 | 직접 계산 | LUT |
| --- | ---: | ---: |
| 137 / 오른쪽 쇄골하 혈관 | 유효 부피 `4.125×10⁻⁹ m³`, 심각도 0.001251 | 손상 부피 0 |
| 281 / 왼쪽 신장 | 유효 부피 `1.346×10⁻⁷ m³`, 심각도 0.004368 | 손상 부피 0 |
| 445 / 경부 식도 | 손상 부피 0 | 유효 부피 `1.541×10⁻⁷ m³`, 심각도 0.014044 |

별도의 등록 탄 114종 × 세 입사속도(342조건, 부위 경계가 없는 0.2837 m 경로)에서 최대 `m` 차이는 `3.45×10⁻⁶`, 계산용 출구속도 차이는 0.00739 m/s였다. 부위 경계가 격자와 어긋난 경우가 더 큰 보간 오차를 만들므로 342조건만으로 오차를 대표하지 않는다.

같은 동결 입력 1,000개를 다시 측정한 최적화 결과는 중앙값 **0.01392 ms**, p95 **0.04637 ms**, 최대 **0.26792 ms**였다. 6회는 0.1 ms를 넘었다. 중앙값·p95 예산은 달성했고 모든 호출의 상한을 달성했다고 주장하지 않는다. 최종 새 입력 캡처와 연사 부하 결과는 성능 담당의 최종 보고를 우선한다.

`tests/training-wound-lut.test.mjs`는 전체 등록 탄의 로드 시점 준비, 342조건 직접 비교, 격자 밖의 부위 경계에서 기존 속도 재주입·질량/에너지 보존·yaw/파편 상태 이어짐을 검사한다. 기존 상처 모델 시험 8개와 합해 **11/11 통과**했다. 원본 직접 소스, 1,000개 실제 입력 gzip, 세 경계 장기 상세와 원시 측정은 최종 검증 폴더의 `performance`에 함께 보존한다.
