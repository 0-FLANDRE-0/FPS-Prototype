## 해석 범위

- passed:true는 기능·측정·바이트 보존 회귀의 통과다. 성능 목표 전체는 allPerformanceTargetsMet:false이며, 최대 빗나감/일부 연사 조건의 미달을 별도 failures에 공개한다.
- 단계별 교대 측정은 같은 Node/V8 프로세스의8개AB/BA블록, 조건당200발이다. 타이머와 AST try/finally는 외부 QA 복사본에만 삽입한다. 프로덕션 HTML에는 없다. 초기15warmup/60표본 조사와 최종 교대 실험을 구별한다.
- 맞은 발 목표는 traceShot p95, 빗나감은 p95와 최대를 모두 공개하고 엄격한1ms최대 기준으로 판정했다. 기록/의료를 포함한 전체 시간은 별도다. 운영체제/GC 지연을 뺀 수치로 합격을 만들지 않는다.
- 남은 주 비용은 타원체/캡슐의 기존 수치 최소거리·경계 탐색이며, 의료/기록의 structuredClone도 그대로 남았다. 이분법 횟수/순서 축소, 근사해, 결과 필드 제거는 바이트 동일성을 깨뜨리므로 적용하지 않았다. GC 겹침은 Node PerformanceObserver에 실제 기록된 경우만 표시한다.
- 모든 발 명중 최대 접촉 부하는 쓰러진 뒤에도 요청을 계속 보내는 사격 서비스 시험이다. 의료 리셋/다음 프레임 이연은 없으며 두 버전의 최종 의료 스냅샷이 정확히 같다. 같은 런타임의 앞선 부하 관측 요약도 보존하며, 플레이어 명중 연사p95는 반복 측정에서3.90–6.34ms로 변했다. 적15발의p95는7.58ms이며 작은 표본이라 첫 발 최대값과 같다. 첫 부하 틱의 cold 비용도 제외하지 않았다.4ms를 안정적으로 보장한다고 주장하지 않는다. 실제 AI/효과/소리는 별도의 브라우저 부하 시험으로 확인한다.
- 브라우저 연사는 기존 무한 디버그AK의 프로덕션 fire()를3틱마다 호출한5초 게임 시간 시험이다. 총기 레지스트리 발사 속도나 수식은 바꾸지 않았다. NPC는 방 안에서 표적을 이미 조준한 조건으로 시작하고 기존 감각/판단/사격을 사용한다. 실시간 벽시계5초에서1200RPM을 유지한 실기기 시험이 아니다.
- SwiftShader 소프트웨어 GPU 완료 시간은 별도로 보고한다. CPU 틱/발당 시간이 줄었다고 Android/iOS GPU FPS나 프레임 끊김이 해결됐다고 주장하지 않는다. 실제 기기는 미검증이다.
- 20%는 효과100%에서 화면의 균일 회색장 sRGB 밝기 비율이다. 강한 흐림과 주변 평균으로 실제 장면의 개별 픽셀 비율은 달라진다. 중앙 작은 원의 가장자리는 기존 터널과 원형 feather 때문에 더 어둡다.
