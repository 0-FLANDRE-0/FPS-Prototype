# v30 Z1 고정 영점 · 조이스틱 진입 조정

v29(`fedda7a440f03cb4f3985f6e656a30c51c38fc7a`) 위에 적용한다. 영점과 자동 달리기 문턱만 변경했다. 원본 `src/**`, 탄약/총기 레지스트리, RK4·저항·중력·유지율·충돌, 관통/방호/의료, 카메라/반동/팔/총구 마커는 그대로다. 터렛·가늠자 눈금 조절·바람·기압·온도·분산 변경은 없다.

## 조작

조이스틱 전방 성분이 **97%**에 도달하면 자동 달리기, **82% 이하**로 내리면 걷기다. 기존88/72%보다 위쪽 끝에서 진입한다. 원형 패드 정규화 후 y값 기준이므로 옆으로 크게 밀면 자동 달리기가 시작되지 않는다. 달리기 버튼·양쪽 Shift·멀티터치·자동 재진입 억제와 속도5.4m/s는 v29 그대로다. 문턱은 게임 **튜닝**이다.

## 발사와 화면 자세

`shotPose()`가 실제 기계식 rear→front 또는 광학 -Z 축을 총기 +X축으로 θ만큼 위로 회전하고, 현재 총기 quaternion으로 월드에 옮긴다. 총구 원점·breech/탄피 회전·벽 앞 총구 검사는 기존 마커/보이는 총열을 계속 쓴다. ADS·비조준·무기 크기/기울임 모두 같은 θ다. 사용 중인 탄이 기준 탄과 달라도 재계산하지 않는다. 조준경 설치/분리 완료를 처리한 같은 tick에서 preset이 바뀐다.

기존 `sightCorrection` 이름/발사 보정을 제거했다. 화면 ADS 정렬은 `visualAlignment`로 유지해 모델 마커선을 눈에 맞춘다. 이 quaternion은 **표시 기하 정렬**이며 영점각에 더하지 않는다. 발사에서 총열 -Z를 출발점으로 삼지 않고 실제 마커선을 출발점으로 삼으므로, M4의 모델 기울기8.065mrad/AK4.429mrad가 θ와 중복되지 않는다. 기본 ADS에서 카메라 조준선 대비 탄자 방향은 θ 하나다. 보이는 총열과 탄자 방향의 작은 차이는 Z1 허용 조건이다. `snapshot.weapon.logicalDirection`은 기존 보이는 총열, `shotDirection`과 `lastShot.direction`은 영점 적용 탄자 방향이다.

## 수치와 대장

뒤 가늠자/접안부를 원점으로 놓고 정지 ADS·크기1에서 조준선을 수평 -Z로 정렬한다. 실제 총구를 같은 변환으로 옮긴다. D는 이 조준선 원점에서 표적까지 수평 거리다. 기존 `flightChord`의 RK4·4m/1⁄120s 상한·도착 chord 보간을 그대로 쓰고 이분법으로 푼다. **빌드 때 조준 장치×기준 탄마다 한 번** 계산하여 생성 JS에 저장한다. 런타임 풀이/탄종별 재영점은 없다. 수치 목표 오차는0.1mm, 실제 이분법 종료 오차는0.00001mm 이하이다.

조준선 높이는 총구 위치에서 연장한 조준선과의 수직 간격이다. M4의 rear 마커 높이68.183mm와 아래63.663mm가 다른 것은 기계식 마커선의 기울기 때문이다.

## 확인한 원문

- **M4/XPS3**: [TC3-22.9, 육군 원문 공개 사본](https://archive.org/download/arn-19927-tc-3-22x-9-c-3-final-web/ARN19927_TC_3-22x9_C3_FINAL_WEB.pdf), §7-36/7-12(PDF130): “The 300 meter zero is the Army standard and works in all tactical situations, including close quarters combat.” §E-9/E-2(PDF216): “The only way to rely on a 300-m hit, is to confirm a 300-m zero.” 공식 Army 호스트는 이번 환경에서503/빈 응답이라 공개 사본의 표제·발행정보·본문을 확인했다. XPS3 전용 EOTECH 공식 권장 영점은 확보하지 못했으며 **육군 CCO에 대한 교범 준용**이다. EOTECH가300m를 지정했다고 주장하지 않는다.
- **ACOG**: [Trijicon .223 Chevron 도면](https://www.trijicon.com/uploads/product-uploads/product-downloads/223_Chevron_Reticle_Dimensions4x32.pdf), “ZERO at 100m”. 현재 셰이더의 셰브론 끝은 광축0이다. 제조사 SKU TA31-D-100309가 도면에 포함된다.
- **Vudu**: [VD1905 RevB SR2/SR3, April2021](https://cdn.shopify.com/s/files/1/0698/3044/3191/files/Vudu_Reticle_Manual_SR2-3_RevB_98e2cd9b-6729-466e-91da-e502b3c21fdc.pdf?v=1763358308), 인쇄8쪽 “All drops are calculated with a 100 yard zero.” 인쇄9쪽 설계 탄은 “75 grain, 2900 fps, .395 BC, 1.5" sight height”. 게임 M855는4.02g/879m/s이며 조준선 높이66.093mm다. 원본 설계 탄과 다름을 보존한다.
- **AK**: [W에서 사용한 Voenizdat1984 원문](https://ru.djvu.online/file/VdNjJdWnyUBdn)의 공개 OCR 본문을 [reader](https://r.jina.ai/https://ru.djvu.online/file/VdNjJdWnyUBdn)로 확보했다. 독립 스캔 PDF 검증은 아니다. §13: “примерно соответствующая прицелу 4 (дальности стрельбы 440 м)”는 **П가4에 대략 대응**한다는 뜻이다. §80/81의 정상 확인은 “Дальность стрельбы 100 м, прицел 3, целик 0.”/100m·가늠자3·+13cm이다. **+13cm를 П 값으로 사용하지 않는다.** 부록4(a)의 가늠자4/100m 행은+24cm다. 이번 П는 교범의 근사 대응4/+24cm를 명시적으로 준용했다. **정확한 П 전용100m 평균 탄착 높이는 원문에 없다.** П=4 또는 П=400m의 정확한 동일성을 주장하거나 게임440m 영점을 따로 맞추지 않는다. 고정 기본값이며 눈금 선택 UI는 없다.

응답 크기/해시와 문장 발췌는 [원문 증거](../downloads/checks-zeroing-v30/sources/)에 남겼다. 표적 인체·관통 관련 원문의 다른 수치는 이번 범위에 사용하지 않았다.

## 검증과 실행

`npm test`, `npm run verify:baseline`, `npm run build:training`을 실행한다. 수치·실제 trace 영점 조건은 `training-zeroing.test.mjs`, 5장치×600틱 전체 총/시점 동작의 v29 동일성은 `check-training-zeroing-motion.mjs`로 확인한다. `check-training-zeroing-browser.mjs`는 실제 tick/fire·인벤토리·사로 충돌/탄착과 원래 입사 경로의 방호·의료 회귀를 확인한다. `check-training-zeroing-offline.mjs`는 계측 없는 최종HTML에서 PC/터치 두 화면과 진입95.45% 미달/풀 입력/히스테리시스·조준·장전 멀티터치를 검사한다.

영점 스크린샷의 FPS 화면은 실제 게임 렌더다. 표적 확대 화면은 **QA 카메라로 실제 표적/탄착을 가까이 본 것**이며 주황 원은 QA 조준점 표시다. 게임에서 분산/호흡을 새 설정으로 없애지 않았다. 정지 영점 검사는 QA 번들에서 기존 breath/walkSway값을0으로 했고, 탄 비행/충돌/영점/총구/발사 함수는 그대로다. AK 확대 화면의+24cm 차이는 지정된 탄착 오프셋이다.

전체 사진/원문/검증 JSON은 저장소에 보존하고 실행 ZIP에는 중복 GLB나 전체 증거를 넣지 않는다. ZIP은20MB 미만이어야 한다. Actions를 사용하지 않으며 `[skip ci]`로 같은 개발 브랜치에 전달한다. Chromium/SwiftShader만 검사했고 Android/iOS 실기기/지속 FPS는 미검증이다.

최종 확인:190/190 테스트, 원본 baseline3,641,864B/SHA`ff330c641f9720e3a960adfd84ee084ea06f215366e88e7f03e14803a176f90d` 동일. 실제5사로 최대 수직 오차0.000214mm, 실제 장착/분리 직후 비조준7발과5장치×600틱 총구/카메라/반동 동일·3개 동일 입사 경로 방호/의료 일치를 확인했다. 비계측 최종HTML은1280×720/844×390 각21조작을 통과했다. 탄착사진은 `downloads/checks-zeroing-v30/*-zero-fps.png`/`*-zero-target.png`, 전체 검증은 `downloads/verification-zeroing-v30.json`을 따른다.

재현 시 동작/브라우저 비교 스크립트는 `../CQB-HTML-v29-baseline`에 위 기준 커밋의 detached worktree를 필요로 한다. 해당 worktree의 `node_modules`는 현재 설치를 공유하고, `dist`는 보존한 v29 HTML/자산을 사용한다. 내장 자산7개와 HTML 템플릿이 동일함을 확인한 경우 현재 `dist`를 복사해 QA 번들만 v29 소스로 교체해도 같은 소스 비교를 재현한다. 일반 `npm test`/빌드는 이 worktree가 필요 없다.
