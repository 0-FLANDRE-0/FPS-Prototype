## 실행과 전달

Node.js 22 이상에서:

```sh
npm ci
npm run dev:training
```

`http://127.0.0.1:5174`를 연다. 소스를 수정한 뒤 `npm run build:training`을 실행하고 새로고침한다. 개발 서버는 변경된 생성 파일을 읽는다. 포트는 `CQB_TRAINING_PORT`로 변경할 수 있다.

같은 로컬 네트워크의 휴대폰에서 개발 PC 주소로 접속하려면:

```sh
CQB_TRAINING_HOST=0.0.0.0 npm run dev:training
```

휴대폰에서 `http://<개발-PC-IP>:5174`를 연다. 클라우드 환경은 별도의 접속 경로가 필요할 수 있다.

```sh
npm run build:training
```

배포물은 약 22.8 MB의 **`dist/CQB_Training.html` 한 파일**이다. Three.js, Rapier JS와 WASM, 총기·병사 GLB와 총 15개 텍스처, 원본 레지스트리 전체, CSS, 임시 합성 오디오와 라이브러리 라이선스를 포함한다. 런타임 CDN·별도 파일 다운로드가 없다. 빌드 정보와 해시는 `dist/training-build-info.json`에 기록한다. 생성물과 `node_modules/`, 검증 스크린샷은 Git에서 제외한다.

WebGL2·WebAssembly를 지원하는 브라우저가 필요하다. 단일 HTML의 오프라인 문서 실행은 검증했다. 현재 작업 환경의 Chromium은 `file://` 탐색을 차단하므로 실제 파일 URL 실행과 각 휴대폰의 HTML 열기 방식은 실기기에서 확인해야 한다. 모바일 파일 앱의 미리보기 대신 브라우저 또는 HTTP 실행이 필요할 수 있다.

### 병사 표적과 피격 구역

오른쪽 통로를 지나 SECTOR 02의 H01 표적에 사격한다. 키1.8m의 고정 A 자세 표적이다. 자세 선택과 제자리 걷기는 비활성화했으며 이전 저장 자세도 A 자세로 불러온다. 피격·방호·의료 상태 확인용으로 사용한다. 설정의 뼈대/피격 영역 표시를 지원한다. 24개 관절을 가진21개 닫힌 인체 영역(17개 기본+관절 보조4개)으로 머리/얼굴·목·흉부·복부/골반·양팔·양다리의 세부 구역을 판정한다. 팔다리는 군복/손/부츠의 원본 표면을 피팅하고 숨은 몸통은 저작 근사다. 좌우는 병사 기준이며 자세의 관절 역변환으로 부위와 방향을 분류한다. [리깅/검증 기록](../../docs/training-soldier-rig-verification.md)과 [고정 표적 v11](../../docs/training-fixed-target-verification.md)을 따른다. 몸통의 별도 이동 캡슐은 플레이어와 모델의 겹침을 막으며 팔다리 탄도 sensor는 이동을 막지 않는다.

설정에서 ‘피격 구역 표시’를 켜면 실제 판정 프로필의 wireframe을 확인할 수 있다. 기본은 꺼짐이다. 판 → 실제 소프트 백커 → 인체 순으로 저지와 관통을 계산하고, 완전 관통하면 후면 방호 및 다음 실제 표면까지 추적한다. 겹치는 관절 메시의 저항은 중복 계산하지 않는다. HUD는 진입 속도·에너지, 세부 부위·인체 경로·체내 정지/출구와 내구도를 표시한다. 최근64개의 사람별 진입 기록에 방호/인체 경로와 전후 잔여 상태를 분리 보관한다. 궤적의 주황은 방호구 관통, 보라는 인체 관통이다. 메뉴의 H01 의료 기록에서 상처·출혈·부위 기능·혈액·의식을 확인한다. 인체 출구 속도와 침착 J도 HUD에 표시한다. 메뉴 일시정지에는 의료 시간도 멈추고 훈련 초기화로 의료 기록을 초기화한다. 의료 상태는 표적 동작에 영향을 주지 않는다.

### 인벤토리와 약실

총기 1개가 주무기 슬롯에 장착된다. 탄창 5개는 독립 아이템이다. 최초 총에는 M855 탄창 29발과 약실 1발, 가방에는 M193·Mk262 30발 탄창 각 1개와 빈 탄창 2개가 있다. M4 호환 탄종 12종은 낱발 아이템 스택으로 각 60발씩 제공한다. 이 훈련용 지급량은 초기화 시 복원하며 저장하지 않는다.

가방은 6×5칸, 탄약상자는 6×4칸이다. 탄약은 1×1칸에 최대 60발, 탄창은 1×2칸, 가방에 넣은 총은 4×2칸이다. 회전·자동 정렬·중량 제한은 아직 없다. 같은 탄종 스택에 옮기면 60발까지만 합쳐지고 나머지는 원래 칸에 남는다. 다른 아이템과 겹치거나 경계를 넘는 이동은 거부한다.

탄약 아이템을 가방 탄창으로 끌거나 선택 후 탄창을 누르면 빈 용량만큼 삽탄한다. 한 발당 0.14초에 실제 원본 스택에서 탄약이 감소한다. 혼합 탄창을 지원하며 나중에 삽입한 탄부터 공급한다. 장착된 탄창은 가방에서 채울 수 없다. 탄창을 총으로 옮기면 교체한다. 장착된 총의 터치/우클릭 메뉴에서 ‘탄창 삽입’을 누르고 가방 탄창을 선택하거나 ‘탄창 제거’를 누를 수도 있다. 같은 아이템을 다시 탭/클릭하면 선택이 해제된다. 선택한 아이템을 다시 누른 채 끌면 이동한다. 가방 탄창을 선택한 뒤 하단 ‘아이템 메뉴’를 누르거나 우클릭하면 ‘탄약 꺼내기’ 메뉴가 뜬다. 꺼내기는 한 발당 0.1초이며 원래 탄종 스택을 채우고 60발을 넘으면 새 칸을 사용한다. R과 화면 장전 버튼은 가방에서 한 발 이상 든 탄창을 먼저 고르고, 해당 탄창들을 위쪽 행부터 각 행의 왼쪽 순서로 사용한다. 모두 탄약이 있으면 좌상단부터 사용하며 탄 수·최근 선택·아이템 생성 순서는 우선순위에 영향을 주지 않는다. 빈 탄창뿐이면 같은 좌상단 순서로 고른다. 드래그나 탄창 삽입 메뉴로 직접 고른 탄창은 그 선택을 따른다.

훈련장 앞쪽 왼편의 5.56 상자에 수평 거리 2.1m 이내로 접근하고 시야가 확보되면 가운데 ‘탄약상자 / 파밍’ 버튼이 뜬다. 열면 내 인벤토리가 왼쪽, 상자 내부가 오른쪽에 표시된다. 상자에는 M4 호환 5.56 탄종 12종을 각 60발 넣었다. 양방향 이동과 상자 탄약에서 가방 탄창으로 직접 삽탄을 지원한다. 상자 탄약은 HUD 보유/예비 탄약에 포함하지 않는다. 닫으면 상자에서 진행 중인 삽탄의 남은 작업을 취소하고 이미 옮긴 탄은 유지한다. 보관함 접근 권한도 해제한다.

약실이 찬 교체는 기존 탄을 유지하고 장전 손잡이를 당기지 않는다. 가득 찬 새 탄창은 30+1발이 된다. 빈 약실·노리쇠 후퇴 고정 상태에서는 삽입 뒤 노리쇠를 풀어 29+1발로 만든다. 빈 약실·닫힌 노리쇠에서는 장전 손잡이를 당긴다. 탄창을 빼도 약실의 한 발은 발사할 수 있다. ‘장전 손잡이 당기기’는 살아 있는 약실 탄을 가방으로 돌려준 뒤 다음 탄을 공급한다. 실제 발사 탄종은 드롭다운 대신 약실에서 읽는다.

탄창 분리·삽입·약실 공급은 60Hz 계산에서 각각 한 번 commit한다. 취소는 이미 옮긴 아이템을 되돌리지 않는다. 교체 전에 기존 탄창을 보관할 별도 2칸과 취소 시 새 탄창을 돌려놓을 원래 2칸을 예약한다. 가방에 여유 2칸이 없으면 교체를 시작하지 않는다. 탄약 꺼내기와 살아 있는 약실 탄 반환도 모든 수납 공간을 먼저 확보한다. 진행 중에는 다른 아이템 이동을 막으며, 취소 시 빈 예약 스택을 정리한다. 탄창과 탄약을 공간 부족으로 버리거나 복제하지 않는다.

내 가방에서 진행 중인 삽탄·재장전은 가방을 닫아도 계속된다. 가방을 열면 이동·사격·시점 입력과 마우스 고정을 해제하지만 훈련 시간은 흐른다. 인벤토리가 화면을 덮는 동안 배경 3D 렌더만 생략해 모바일 GPU 부하를 줄인다. 계산·UI·효과 수명·총기 부품 자세는 계속 갱신하고, 닫으면 최신 상태를 다시 그린다. 총을 가방에 넣고 다시 장착해도 내부 탄창·약실 상태가 유지된다. 드래그는 잡은 칸 위치를 유지하며 pointer cancel·capture 상실·닫기에서는 이동을 확정하지 않는다. 탄자 질량을 완성 탄약 아이템 무게로 사용하지 않는다.

### 전체 데이터와 반동

`scripts/training-catalog.mjs`는 원본 manifest 순서로 레지스트리 초기화·source switch·파생 필드 복원을 실행한다. 114종 탄약, 17종 총기와 부품·방탄복·플레이트·헬멧·추가 보호구 등 12개 레지스트리 전체, 최종 탄약·방호·의료 보조 테이블을 생성 모듈에 기록한다. 사용하지 않는 데이터도 HTML에 포함되며 원본 ID를 보존한다. 현재 3D 사용 무기는 M4A1 하나이고 선택 가능한 탄약은 호환 12종이다. 데이터 포함 자체는 다른 무기의 모델·동작이나 방호·의료 계산 연결을 의미하지 않는다. 모든 원본 소스 해시를 기록하며 빌드마다 재생성한다.

첨부 모델에 맞춰 M4의 iron / 14.5인치 총열 / A2 소염기 / 별도 전방 손잡이 없음 구성을 원본 resolver로 계산한다. 총열 배율은 기본 무기 배율을 대체하며 중복 곱하지 않는다. M855는 4.02g, 879m/s, 탄자 운동량 약 3.534 N·s다. 원본 `computeProjectileKinetics`를 재사용하되 반동 충격에는 반올림 전 운동량을 사용한다. 이 데이터와 수치는 원본 게임 기준이다.

탄자 운동량에 추정 가스 보정 1.35를 적용하고, 총기 질량 3.07kg으로 후퇴 응답, 추정 모멘트 암 0.045m·피치 관성 0.14kg·m²로 회전 응답을 계산한다. 이전 추정 관성 0.12 대비 위로 들리는 응답을 약 14% 줄였으며 탄자·가스 충격량, 후퇴·좌우 응답과 단발/연발 복귀 계수는 유지한다. 사수 반응 지연·강성·감쇠·잔류 각도를 따로 둔다. 단발 안정화 계수는 0.94, 연발은 0.84이며 연발 판정은 AUTO 모드에서 이전 발사 후 0.18초 이내의 후속 발사다. AUTO의 첫 발/한 발 탭도 단발 응답이다. 사격이 멈춘 뒤 단발 0.16초/연발 0.26초부터 잔류 목표를 더 줄여 강하게 복구한다. 정지 사수의 M855 계산 fixture에서는 단발 최고 상승의 98% 이상, 10발 연사의 85% 이상이 복구된다. 이 비율은 관측 테스트 결과이고 계수 자체와 같지 않다.

작은 잔류 오차는 직접 보정한다. 아래로 보정하면 자동 복귀할 여분부터 줄이고 최종 잔류 목표도 제한해 이중 보정·옛 조준 방향으로 되끌기를 피한다. 연사 충격은 누적하고 앉기·이동은 지지 응답만 바꾸며 발사 충격량은 그대로다. 총기 표시 크기·높이는 질량·관성 계산과 독립이다. 가스·관성·지지·복귀 계수는 실측값이 아니며 실제 M4 재현에는 관측 자료로 조정해야 한다.

총구 자세를 확정한 발사 사건에서 탄약을 한 번 소비하고, 그다음 충격이 이후 발사에 영향을 준다. 카메라는 움직인 총을 따라가며 작은 시각 충격도 같은 사건에서 만든다. 화면 흔들림을 끄거나 렌더 FPS를 바꿔도 논리 반동 상태를 바꾸지 않는다. 최대 조준 각도에서는 지지 관절의 이동 한계로 초과 운동을 흡수해 숨은 반동 누적으로 입력이 먹히지 않는 상태를 막는다. 기존 `recoilBase`·탄약 `recoil` 기반 산포 감소를 추가로 중복 적용하지 않는다.

Rapier capsule과 캐릭터 컨트롤러가 바닥·벽·엄폐 충돌을 처리한다. 앉기와 기립은 발 위치를 유지하며 기립 공간을 검사한다. 사용자 제공 `aim_rig.html`을 참고해 **입력 → 총기 방향 → 카메라 추종** 순서로 움직인다. 총이 먼저 방향을 잡고 카메라가 늦게 따라오며, 드래그를 멈추면 카메라가 총의 방향으로 수렴한다. 호흡·보행·반동은 총과 카메라에 다른 비율로 전달된다. 기본 바디캠 프리셋의 추종 속도는 3.5, 최대 이탈 범위는 20°이며 ADS에서는 추종을 빠르게 하고 이탈 범위를 줄인다. 벽 앞에서는 총을 낮추고 총구까지의 차폐를 검사해 벽을 넘어 발사하는 것을 막는다.

ADS의 정지 자세는 실제 가늠자 구멍 중심과 가늠쇠 끝을 연결한 선에 눈을 맞춘다. 눈과 가늠자 사이는 기본 7.5cm다. v20에서는 개머리판 접점을 늦게 따라오는 견착 방향에 붙이고 총을 그 점 둘레에서 회전시킨다. 이동·반동은 두 조준기의 정렬을 잠깐 흐트러뜨린다. 견착 회전 지연에는 기본 0.022rad 한계를 두며 멈추면 다시 정렬한다. 표시용 카메라 위치 흔들림은 ADS에서 줄이고, 조준기 움직임은 계산된 총 자세에서 만든다.

보행 중 총에 좌우·상하·앞뒤 위치 이동과 기울어짐을 더했다. 보행 주기는 실제 이동 속도로 진행하고, 벽에 막히거나 멈추면 정지하며 진폭이 서서히 줄어든다. ADS에서도 작은 위치 이동과 회전은 남긴다. 기본 시야각은 66°, ADS는 52°다. 비조준 기본값은 총기 크기 115%·높이 −1cm이며, 이전 배치에서 오른쪽으로 1.5cm 옮겼다. 보행의 총기 상하 위치·피치와 카메라 상하 움직임은 25% 줄였다. 총을 위로 올리고 기울임을 더해 몸통을 보이게 했으며, 카메라와의 거리를 늘려 앞뒤 크기 차이가 과장되는 원근감을 줄였다. ADS에서는 원래의 보정 크기로 부드럽게 돌아온다. 확대·높이·보간은 모델과 총구·탄피 배출·조준기 기준점에 함께 적용하므로 표시 총구와 발사 위치가 일치한다. GLB 파일의 형상·텍스처는 그대로다.

실제 발사는 계산 틱의 총구 위치와 총열 방향에서 시작하며 가장 가까운 Rapier 접촉부터 원본 장애물 관통·도탄·잔여 탄도 계산을 이어간다. 화면 중앙으로 발사를 수렴시키지 않는다. 확정 발사 사건 하나에서 섬광·빈 탄피·접촉 자국·먼지·임시 총성을 생성하고 탄약을 한 번 소비한다. 모델의 노리쇠·탄창·장전 손잡이에 절차적 움직임을 추가했다. v20의 1인칭 팔·AK 클립과 별도로 사실적인 녹음 총성은 후속 작업이다. 장애물 진입·출구와 표적에는 자국·재질별 색의 입자 효과를 남긴다. 탄피는 제한된 풀에서 움직이며 바닥에만 간단히 튕기는 시각 효과다.

일시정지 메뉴의 ‘조작·화면·훈련 설정’에서 **시점·조준 감도 25~200%와 ADS 감도 25~100%**를 따로 조절한다. ADS 감도는 일반 감도의 배율이며 기본은 55%다. 안정형·중간·바디캠 프리셋, 시점 추종 속도·이탈 범위·총기 반응 속도·시야각도 조절할 수 있다. **비조준 총기 크기 100~155%, 총기 높이 −4~+4cm, 총기 움직임 0~160%**를 추가했다. 높이 설정은 들어 올린 비조준 기준 자세의 오프셋이며 기본값은 −1cm다. ADS 높이는 유지한다. 총기 움직임은 보행 진폭과 견착 회전 지연을 조절하며 사격 반동은 유지한다. 프리셋 변경은 선택한 감도·총기 크기·높이·움직임 강도를 유지한다. 설정은 가능한 경우 localStorage에 보존하고 훈련 초기화에서도 유지한다. 이전 저장값에 새 항목이 없으면 기존 감도를 유지하면서 새 기본값을 적용한다. 파일·저장 차단·opaque origin에서는 오류 없이 현재 세션에 적용한다. 감도·총기·카메라·궤적 초기화는 별도 버튼이다.

설정의 **탄 궤적 표시**를 켜면 최근 5초·최대 24발의 실제 판정 경로가 남는다. 일반 구간은 연노랑, 관통 후는 하늘색, 도탄 후는 분홍색이며 장애물 너머까지 보인다. 원본 안정성 감쇠·관통 후 흔들림을 그대로 표시한다. 기본은 꺼짐이며 저장·복원을 지원한다. 끄기/훈련 초기화는 선을 지우고, 설정 초기화는 표시를 끈다. [상세 설명](../../docs/obstacle-penetration.md#탄-궤적-표시)을 따른다.

카메라 흔들림, 화질, 30/60 FPS 제한, 소리, 조준 가이드도 조절한다. 카메라 흔들림 설정은 총구 판정을 바꾸지 않는다. 기본은 30 FPS 렌더와 DPR 상한 1.35이며 절약 모드는 DPR 1이다. 계산은 60 Hz 고정 틱, 프레임당 최대 6틱을 처리한다. 긴 지연은 제한하므로 실제 성능이 부족한 기기에서 시간이 느려질 수 있다. 목표 프레임을 보장하는 측정 결과는 아니다.

세로 회전·창 비활성·앱 전환에서는 일시정지하고 held 입력과 누적 시간을 비운다. 가로화면으로 돌아와 명시적으로 재개한다. Pause 시 마지막 계산 자세로 총을 고정해 RAF가 중단되어도 표시 총구와 논리 총구가 맞는다. 초기화는 플레이어·탄약·표적 기록·효과를 되돌린다.

## 에셋과 크레딧

원본은 Firewarden3D의 [M4A1](https://sketchfab.com/3d-models/m4a1-40d8ef818c7549a896371cbb1f64fec6), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)이다. 모델 메타데이터의 출처와 라이선스를 `assets/credits.json` 및 게임 크레딧에 보존했다.

원본 9,211,460바이트에서 총기 한 개와 빈 탄피를 추출해 5,821,164바이트로 준비했다. 중복 전시 총기·사용하지 않는 탄약 객체·사용하지 않는 vertex 범위를 제외하고 root 축을 정렬했다. 유지한 형상·텍스처는 원본 그대로다. 총기 30,007삼각형과 탄피 412삼각형, 두 재질, 여섯 내장 PNG를 사용한다. 원본에 skins와 animations가 없으므로 이번 움직임은 별도 절차적 연출이다.

원본 SHA-256: `472a720bf2d594399b9050a6a79ce5e459e5c3f895543e44224b2a02b8183355`.
준비본 SHA-256: `30c19debb065a881819a4037434da767418925010a82982b05908ac0d87f8fdd`.

원본은 수정하지 않았다. 준비본을 재현하려면 Python 표준 라이브러리로:

```sh
python scripts/prepare-training-asset.py /path/to/original-m4a1.glb
```

검토한 원본 해시가 다르면 추출을 중단한다. 새로운 모델의 node 번호에 이 스크립트를 그대로 적용하지 않는다. Three.js MIT와 Rapier Apache 2.0 전문은 생성 HTML의 `third-party-licenses`에 포함한다.

병사 모델은 Muhamad Mirza Arrafi의 [Soldier Character](https://sketchfab.com/3d-models/soldier-character-dc88bfc47861426e8132b7b8d5174b48), CC BY 4.0이다. `assets/soldier-credits.json`과 게임 내 크레딧을 유지한다. 원본9,723,700 bytes 파일은 보존한다. 빌드에서 높이1.8m로 정규화한 파생 GLB에24개 관절의 skin과4개 애니메이션 클립을 추가한다. 원본22,793삼각형·5개 재질·UV·인덱스·9개 내장 텍스처를 유지한다. 게임에서는 A 자세만 사용한다. 기존 클립은 편집용 자산에 보존하며 재생하지 않는다. `dist/soldier-rigged.glb`는 Blender 등에서 열 수 있고 HTML에도 내장한다. 원본 hash와 전달 HTML은 빌드에서 검증한다. 내장으로 HTML이 약 13.0MB 증가하고 병사 텍스처의 RGBA+mipmap 추정 GPU 메모리는 약 44MiB다. 실기기 성능 측정값은 아니다.

PC의 Tab·좌클릭 드래그/사격·총 우클릭 탄창 메뉴와 오프라인 문서 부팅·사격도 검증한다. 결과는 `artifacts/training/checks.json`, 스크린샷은 같은 폴더에 저장한다.

결과에는 실행한 focus와 빌드 해시를 기록한다. `full`은 카메라·설정·회전·Pause 회귀까지 실행하고 `inventory`는 이번 격자·파밍·단발/연발 복귀·PC 마우스 변경에 집중한다. `tuning`은 모바일 두 해상도와 PC에서 선택 해제·드래그 유지·장전 우선순위·낮춘 총구 상승 및 단발 복귀·오프라인을 확인한다. `desktop`은 모바일 단계를 생략하고 PC·오프라인을 확인한다. `offline`은 네트워크 OFF 문서에서 부팅·사격·궤적·병사 모델·피격 구역과 저장 차단 대응만 확인한다. 소프트웨어 GPU 검증의 상호작용 구간은 절약 화질(DPR 상한 1)에서 실행한다. 기기 에뮬레이션의 DPR은 2다.

이 검증은 Chromium 소프트웨어 WebGL 환경의 기능 확인이다. 실제 Android Chrome·iOS Safari의 조작감·렌더 시간·메모리·발열·파일 실행은 아직 검증하지 않았다. 원본 HTML과 2D 조립 결과의 바이트 동일성은 유지한다. 원본의 기존 C2 실패 1개와 방호 validator 경고 1개는 기존 기준에 남아 있다.

상처·출혈·생리 연결과 원본 context 검증은 M/P에서 완료했다. 실기기 피드백·의료 상태에 따른 동작·치료·NPC와 레이드는 후속 범위다. 상세 계획은 [레이드 개발 계획](../../docs/raid-prototype-plan.md)을 따른다.
