# 병사 리깅·움직이는 피격 영역 검증 (soldier-rig-v9)

## 범위

사용자가 요청한 몸통·팔다리 메시 피팅과 뼈대 작업, 이후 지적한 손·발의 형상/변형을 구현했다. v8 `3b1906884dcb7977f37e9268d2a20bf8703f9dbf`에서 이어지는 누적 빌드다. 방호 저지·둔상·내구도·인체 저항·의료 계산은 요청대로 이후 단계로 남겼다. 기존 6B45 소프트9개·판2개·헬멧1개는 피복 관측만 하며 Br5/19mm 메타데이터와 판 우선 처리 순서를 유지한다.

설정에서 A 자세(기본)·서기·조준 자세·웅크리기·제자리 걷기를 선택하고 뼈대/피격 영역을 독립 표시할 수 있다. 설정 저장/프리셋 유지/초기화를 지원한다. 걷기는 게임 시간에 따라 제자리에서 재생하며 메뉴에서는 멈춘다. 무기 쥐기·손가락 개별 움직임·이동하는 적 AI는 포함하지 않는다.

## 원본과 파생 자산

- 원본 `apps/training/assets/soldier-character.glb`: 9,723,700 bytes, SHA-256 `f38f736aa92ca01564cbc3d6526655fc639677eedd2e0b7f939eb4ca3e0d978a`. 원본 파일·라이선스·크레딧은 보존했다. 원본에는 skin/animation이 없었다.
- 파생 `dist/soldier-rigged.glb`: 10,579,016 bytes, SHA-256 `0ca0af733fd5c1bd6a601ce098ca7d3551442aa7605982c67819f5c71c4c6042`. 빌드 때 재생성하며 게임에 내장하고 ZIP에도 별도로 제공한다.
- 키1.8m로 좌표/법선을 정규화하고 JOINTS_0/WEIGHTS_0·inverse bind matrices·24개 관절을 추가했다. 원본22,793삼각형·16,165정점·5개 재질·UV·인덱스·9개 내장 텍스처의 바이트는 유지한다.
- 24개는 몸통6개와 양쪽 쇄골/상완/전완/손/대퇴/하퇴/무릎 보호구 보조/발/발끝이다. 발끝 관절은 향후 작업용이며 현재 부츠는 발 관절에 고정한다. 손가락별 관절은 없다.
- GLTF 표준 애니메이션4개(`standing`, `aim`, `crouch`, `walk`)를 넣었다. 게임은 같은 관절 계약의 런타임 자세를 사용한다. 걷기 클립은1.2초/24구간이며 다른 클립은 정적 자세다.
- Blender4.3.2에서 파생 GLB를 가져와 armature1개·24bones·스킨 적용 메시5개·애니메이션4개·내장 텍스처9개를 확인했다. 이는 전문 애니메이터의 리타기팅/변형 품질 검수를 의미하지 않는다.

## 피격 형상과 자세 연결

원본 `Body`8,364삼각형의 연결 요소(시작 삼각형0/1599/2138: 양팔과 바지/부츠)를 선택했다. 상완·전완·대퇴·하퇴·골반은 원본 표면과 교차한 단면 샘플에서 닫힌 피팅 메시를 만든다. 원본 표면이 없는 샘플과 단면 끝 캡은 저작 근사다. 원본에 조끼 아래 완전한 맨몸 몸통이 없어 흉부·복부·목은 숨은 몸의 저작 형상이다. 군복의 외곽 피팅은 해부학적 장기나 조직 두께가 아니다.

손은 손목 경계를 선택한 원본 정점, 발은 부츠/밑창 정점의 convex hull이다. 손끝·엄지·발끝·밑창의 윤곽을 보존하고 기존 원통형 피팅을 교체했다. 손가락 사이 공간/부츠 주름은 hull이 메우므로 삼각형 전체를 그대로 복제한 판정은 아니다. 부츠 가중치는 발 관절에 고정하여 굽힐 때 바닥이 찌그러지는 문제를 줄였다. 팔의 손목 장식은 팔에, 무릎 앞 보호구는 대퇴/하퇴 중간 회전의 보조 관절에 연결했다.

추가 확인에서 목 보호대 상단188개 원본 면 중 일부가 머리 표면 샘플로 쓰인 것을 발견했다. v8의403개 표면 샘플 중97개가 이 범위였으며, 보호대 전체 연결면을 머리 샘플 후보에서 제외했다. 현재 원본 얼굴/턱/뒤목308개와 숨은 두부/보호대 뒤 턱652개 저작 샘플이다. 보호대 외곽을 머리로 부풀리던 문제를 제거했고 머리 자체는 보호대 안쪽에 남는다. 원본 보호대138삼각형/저작 피복 상단 경계는 이 확인에서 바꾸지 않았다. 시각 보호대의 상단 가중치도 흉부로 연결했다.

17개 기본 영역에 양쪽 팔꿈치/무릎의 작은 저작 보조 영역4개를 더해21개 닫힌 피격 sensor를 사용한다. 관절을 굽힐 때 생기는 단절을 메운다. 기존8개 의료 저장 부위와 이동용 몸통 capsule은 유지한다. 방호/인체 경로 길이를 계산할 다음 단계에서는 겹치는 영역을 합집합으로 처리해야 하며 중복 길이를 더하면 안 된다.

시각 스킨과 충돌 sensor는 한 런타임 뼈대를 공유한다. 각 sensor는 한 관절의 bind→pose 행렬로 이동/회전하고 진단 표시는 같은 정점과 변환을 쓴다. 갑옷도 머리/흉부/골반/상완 관절에 함께 연결하고 곡면 판 LOS의 pose를 갱신한다. 피격 주소를 나눌 때 관절의 역행렬로 bind 좌표를 복원하므로 웅크린 무릎이 발로 잘못 분류되지 않는다.

Rapier의 world broadphase는 수동 위치 변경 직후 갱신되기 전일 수 있다. 일반 장애물은 기존 world raycast를 유지하고 인체는 현재 collider의 직접 raycast 결과와 가장 가까운 거리를 비교한다. 이 때문에 자세 변경 후 추가 physics step 없이 올바른 위치를 판정한다. 기존 player step과 탄도 RNG는 바꾸지 않았다.

## 검증 결과

- 공식 `npm test`: **84/84**, 실패/skip0. 원본 바이트/스킨 유효성·재생성 동일성·닫힌 메시 edge/winding·보호대의 머리 표면 샘플 배제·원본 표면 정합·자세 IK/복원·역행렬 주소·즉시 Rapier raycast·진단 변환·잔여탄도/RNG 관측성을 추가 확인했다.
- `npm run verify:baseline`: 원본3,641,864 bytes / SHA-256 `ff330c641f9720e3a960adfd84ee084ea06f215366e88e7f03e14803a176f90d`, identical. v8과 원본/레거시/자산·조준/반동/렌즈·탄도/레인·인벤토리 등91개 보호 파일도 바이트 동일이다.
- 외부 QA 번들: v8과 동일600틱/실제 발사6회에서 camera/logical muzzle/direction/발걸음 spring 기록 전체가 정확히 같다. 원본 조준·발걸음·탄도 계산을 재작성하지 않았다.
- 실제 `tick`→`fire`→AimState→Rapier 경로의14개 고정 사격: v8의 얼굴/턱/정수리/헬멧 테두리/전방 목/목 구멍/측두/후두와 서기 손·조준 손·웅크린 흉부/무릎/부츠와 목 보호대 상단. 올바른8개 부위·세부 주소·피복·탄약 보존을 확인했다. 헬멧만 스친 탄은 인체 적중0이다. 이 기하 fixture만 호흡을 끄고 반복 조준하며 원본 `fire()`를 실행한다.
- A/서기/조준/웅크리기/걷기 각각에서 hull 원본 정점과 실제 SkinnedMesh의 정점을 비교했다. 손 최대 차이는 조준에서1.914mm(손목 blended weight), 나머지 자세는1e-7m 미만이다. 부츠는 모든 자세1.4e-8m 이하이고 밑창 최저Y는0 이상이다. 관절 근처의 blended 시각 표면과 단일 관절 피격체가 모든 곳에서 완전히 일치한다고 주장하지 않는다.
- 실제 전달 HTML을 네트워크 OFF 상태에서844×390 터치/1280×720 키보드·마우스로 부팅·이동·사격·재장전·인벤토리·탄약 보존·설정 저장/초기화·제자리 걷기를 확인했다. 브라우저 오류/외부 요청0이다. file URL 정책 제한으로 정확한 HTML 바이트를 메모리에서 제공했다. S24 실기기/file:// 직접 실행 검증은 아니다.

개발 중 목 하단 틈·허리에 연결되어 떠 있던 손목 장식·손/부츠의 원통형 외곽·무릎 보호구의 변형·Rapier의 오래된 pose query를 수정했다. 이전 팔/손 테스트 좌표 일부는 원본 표면 바깥이었다. 원본 표면을 대조한 뒤 전완 `[.445,1.10]`, 손 `[.565,.958]`로 시험 좌표를 고쳤으며 실제 게임의 자세별 사격도 별도로 검증했다. 외부 하네스의 모델명 조회와 Blender의 display helper 집계 문제도 바로잡았다. 이 개발 중 실패를 공식 최종 성공으로 혼합하지 않는다.

## 재현과 산출물

```sh
npm ci
npm test
npm run verify:baseline
npm run build:training
# v8 소스를 별도 worktree에서 설치/빌드한 후 경로를 지정한다.
CQB_BASELINE_ROOT=/path/to/v8 CQB_QA_ONLY=1 node scripts/check-training-soldier-rig.mjs
CQB_SMOKE_ONLY=1 CQB_OFFLINE=1 node scripts/check-training-soldier-rig.mjs
# 선택 검증: Blender 설치 필요, CI/공식 npm suite 밖의 검사다.
blender --background --factory-startup --python scripts/check-training-soldier-rig-blender.py
```

외부 하네스 결과는 `artifacts/soldier-rig/`에 생성한다. 선택적으로 `CQB_RIG_CASE`로 사격1개만 확인할 수 있지만 이를 전체 성공으로 간주하지 않는다. `CQB_SOURCE_ROOT`/`CQB_HTML`로 대상 소스/HTML을 지정할 수 있다. QA HTML/API는 전달 HTML·ZIP에 없다. 최종 검증과 화면은 `downloads/checks-soldier-rig/`, 버전 정보는 `downloads/training-build-info-soldier-rig-v9.json`, 종합 검증은 `downloads/verification-soldier-rig-v9.json`, 실제 Actions ZIP 대조는 `downloads/delivery-soldier-rig-v9.json`을 따른다. 이전 v8 이하 기록은 보존한다.

이 단계는 리깅과 움직이는 판정의 기반이다. 개별 손가락/무기 그립·뛰기/사망/넘어짐·terrain IK/발 미끄러짐·NPC locomotion·새 의료/방호 실행은 후속 작업이다. 포즈의 군복/장비 변형도 전문 아트 검수 여지가 있다.
