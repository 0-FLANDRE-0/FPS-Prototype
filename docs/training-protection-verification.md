# H01 방호 저지·인체 저항 v10

사용자가 요청한 방호 저지와 인체 저항을 v9의 리깅/피격 메시 위에 연결했다. 장착은 **6B45 소프트 + Granit Br4 전후면 판 + 6B47 헬멧**이다. 기본 브랜치에 병합하지 않았고 원본 `src/**`, `CQB_Tactical.html`, 모델 원본과 v9 파생 GLB를 보존했다. 다운로드/커밋/해시는 `downloads/training-build-info-armor-body-v10.json`, 검증은 `downloads/verification-armor-body-v10.json`, 실제 ZIP 대조는 `downloads/delivery-armor-body-v10.json`을 따른다.

## 실제 처리

표시 옵션과 관계없이 탄과 만난 메시를 판정한다. 같은 면의 판/조끼가 모두 교차하면 **판 → 해당 면의 소프트 백커 → 인체**다. 판에 저지되면 소프트와 인체는 미도달이다. 인체를 완전 관통한 경우에만 다음 실제 표면을 조회하므로 후면 판/소프트와 헬멧 후면도 별도로 처리한다. 반대편 소프트를 진입 판의 백커로 쓰지 않는다. 사선에서도 외피와 판 사이의 공기 간격 때문에 소프트가 먼저 저지하지 않게 했다.

내구도는 판 전후면, 조끼 소프트, 목/낭심/어깨 부속, 헬멧의 소유자별로 보관한다. 원본 전체/국부 손상·인접 전파와 내구도 방호력 곡선을 사용한다. 관통 판의 잔여탄을 백커가 잡았으면 원본의 `partial_or_backer_stopped` 마모 분류다. 새 훈련 시작/초기화로 장비도 복원된다. 양 어깨는 기존 프로필의 동일 부속 소유자를 공유한다. 국부 구역은 원본의 center/upper/lower/edge/side 분류이며 정밀 탄착별 파괴 메시나 타일 시뮬레이션은 아니다.

| 장비 | 원본 게임 ID/값 | 이번 적용 |
|---|---|---|
| Granit Br4 | `plate_granit_br4`, ceramic hard 51, 15 mm, 내구도48 | 실제 곡면 재료 경로 / 15 mm × hard 방호값. ICW 외부 백커 최소18. 원본 backingArmor5를 외부 백커로 대체하지 않음 |
| 6B45 본체 | `armor_6b45_basic_test`, aramid 32, 내구도44 | 전후면/측면 원본 소프트 표면 |
| 목 | `6b45_neck`, aramid 33, 내구도26 | 기존 목/전면 목의 원본 표면 |
| 어깨 | `6b45_shoulder`, aramid 32, 내구도32 | 원본 좌우 어깨 표면 |
| 낭심 | `6b45_groin`, aramid 33, 내구도32 | 원본 낭심 표면 |
| 6B47 | `helmet_6b47_test`, skull shell23 / temporal22, liner8, aramid, 내구도42 | 기존466삼각형 헬멧 피복 + 원본 shell/liner 판정과 탄종 페널티. 얼굴/끈/고글에 피복을 추가하지 않음 |

값은 원본 레지스트리의 source switch/파생 필드를 초기화한 **최종 게임 값**이다. 이전 선언의 plate max55/soft max55 대신 최종48/44를 사용한다. Br4는 사용자가 지정한 게임 판이며 실물 6B45의 표준 장착판을 검증했다는 뜻이 아니다. 6B47 두께는 원본에 없으므로 임의의 mm나 판 LOS 배율을 붙이지 않는다. M855는 원본 헬멧 페널티8이 적용되어 새 skull shell의 유효 기본값은15, liner는0이다.

## 원본 재사용 경계

`scripts/training-protection.mjs`가 검토한 선언만 별도 factory로 추출한다. 원본 파일과 선언/인체 깊이 블록의 SHA는 빌드 정보에 기록한다. `armor-resolution.js`의 관통 확률·잔여 위협 패킷·ICW 충족도·백커 시도/확률 게이트·헬멧 페널티, `damage-outcomes.js`의 재질별 관통력, `armor-durability.js`의 canonical 탄종·kinetics·내구도 계산, `body-trauma.js`의 부위 저항/terminal 보정과 깊이 분기를 재사용했다.

부위/피복은 실제 3D 교차가 결정한다. 원본 `rollHitLocation`/`rollProtection`의 추상 피복 확률을 다시 굴리지 않으며 의료 `resolveImpact` 전체를 호출하지 않는다. `src/**`와 원본 HTML은 무수정이다. 관통 판정에 사용하는 난수는 기존 shot-local RNG다. 방호 판정을 모두 마친 뒤 원본 마모가 난수를 소비한다. 인체 경로 저항은 결정적이다. 원본의 0..10 혼합 입력 정규화는 이미0..100으로 계산된 3D 잔여탄에 다시 적용하지 않는다. 명시적0/낮은 잔여값을 새 탄약의 값으로 복원하지 않고 관통력·속도·damage·안정성은 증가하지 않게 제한한다.

아래는 **새 3D 연결 규칙/프로토타입 튜닝**이며 원본과 완전히 같은 2D 시스템 또는 실측 탄도라고 주장하지 않는다.

- 판 LOS는 닫힌 곡면 메시의 실제 재료 구간이다. 분리된 판 교차 사이의 공기 구간은 재료로 채우지 않는다. 두께/곡률·장착점은 기존 저작 판 형상이며 명목 두께를 Br4의15mm로 바꿨다.
- 소프트는 mm 두께 없이 기본 방호값을 사용한다. 법선 대비 경로 비율 `r`에 대해 `min(1.6, 1 + max(0, r - 1.5) × 0.35)`를 곱한다. 1.5까지 증폭 없음. 임계값1.5/계수0.35/상한1.6은 이번 어댑터 튜닝값이다.
- 원본 방호는 잔여 관통력을 주지만 3D 방호 출구 속도를 정하지 않는다. 이번 연결은 `vAfter = vBefore × sqrt(penAfter / penBefore)`로 제한하고 damage도 잔여 비율로 줄인다. 에너지를 늘리지 않는 게임용 연결이며 실측 감속 모델이 아니다. 하드 관통 뒤 안정성은 원본 residualIntegrity로 낮추고 기존 `applyLegacyPenetrationWobble`을 3D 입사면에 적용한다. 소프트 통과는 원본 진입 맥락의 `max(0, effectivePen - armor × 0.85)` 잔여 규칙이다. ICW 백커 저지 실패에는 보통 소프트 판정을 다시 돌려 이중 차감하지 않는다.
- 인체는 자세를 따르는21개 닫힌 메시의 **연속 구간 합집합**이다. 관절 보조/인접 부위가 겹쳐도 그 길이에 저항을 중복 부과하지 않는다. 각 세부 구간은 원본 부위 cost × terminal 계수 × 실제 길이 / 기준 길이로 계산한다. 피부 진입3과 출구 잔여 임계값, surface/shallow/deep/near-exit/through 분기는 원본이다.
- 인체 기준 길이는 head190, neck120, chest/abdomen240, 팔90, 다리150 mm로 정했다. 숨은 몸통 및 군복 피팅은 해부학 조직 두께 실측이 아니다. 얼굴은 기존 head 메시의 세부 주소를 보존하고 저항은 head 표를 사용한다. 체내 정지 지점은 구간별 저항 예산이 소진되는 위치이며 exit-lodged는 마지막1mm 이내로 표시하는 근사다.
- 인체 출구 속도0.5/잔여 damage0.4는 원본 continuation packet 규칙이다. 잔여 관통력6 이상이면 3D에서 모든 부위의 출구 이후 경로를 이어 조회한다. 원본 2D 의료의 head/neck 후속 ray 제한은 그대로 사용하지 않는다. 최대 거리에서 인체가 잘렸으면 실제 출구/exit wound를 주장하지 않는다.

## 기록과 화면

`trace.armorResults`에 단계/유효 방호·관통력/확률/백커/마모/전후 잔여 상태, `trace.bodyHits`에 진입 주소·저항 구간/길이·깊이·정지/출구·전후 상태를 기록한다. 마지막 정지점 `trace.hit`은 후면 판/벽일 수도 있으므로 인체 적중 기록은 별도 진입 기록에서 만든다. 기록의 속도/J는 인체 **진입 시점** 값이다. 한 발이 같은 사람의 여러 부위를 지나도 사람별 카운트는 한 번이며 세부 경로는 모두 보관한다. 명중 HUD는 방호구 저지도 표적 적중으로 세지만 인체 기록/카운트는 실제 피부 접촉에만 생성한다. 의료 damage/상처/HP로 해석하지 않는다.

HUD는 저지·소프트 미도달·통과 후 소진·체내 정지·완전 관통과 장비 내구도를 보여준다. 궤적은 기존 일반(노랑)/장애물 관통(청록)/도탄(분홍)에 방호구 관통(주황)/인체 관통(보라)을 추가했다. 5초/최대24발과 꺼짐 기본을 유지한다. 진단 표시를 꺼도 방호 계산은 실행된다.

## 검증

공식 `npm test` **99/99**와 원본 baseline 바이트 동일성을 확인했다. 기존84개 중 공간 관측 fixture는 명시적 `geometryOnly:true`로 좌표/메시/주소/관측 난수 불변성을 계속 검증한다. 제품 기본은 방호 실행이며 새15개 fixture는 이 기본 경로와 실제 방호/인체 함수를 검증한다.

새 검증에는 M4 탄종12개 × 재질3개 × 방호값4개의 **144개 원본 VM 잔여/내구도 대조**, 헬멧 탄종 보정·ICW 충족도, 낮은 잔여값 부활 방지, 판 먼저/백커 저지 및 partial wear, 사선 LOS·소프트 임계 증폭, 출구/피부·얕은/깊은/exit-lodged, 자세5개 메시 합집합, 실제 후면 판/소프트 및 헬멧 통과, 반복 피격/초기화, 엄폐 뒤 장비 미손상, 분리된 곡면 판의 공기 구간, 두 번째 표적에 잔여탄 전달/기록 분리가 있다.

외부 브라우저 범위는 `scripts/check-training-protection.mjs`와 검증 JSON에 기록한다. 배포 HTML의 터치844×390/마우스1280×720 실제 UI와 네트워크 OFF 문서, 별도 QA 번들의 고정 발사/원본 난수·실제 인벤토리 pack/reload/rack·탄약 보존/내구도 reset, v9 대비600tick·6발의 총구/방향/카메라/걸음 동일성을 확인한다. QA는 조준의 호흡을 끄고 위치/자세를 고정하지만 발사·탄약 소비·AimState·Rapier·방호 계산은 제품 함수다. QA HTML/가변 접근 인터페이스는 배포물에 포함하지 않는다. 브라우저 고정 발사는 게임 난수를 강제로 바꾸지 않는다.

초기 harness는 inventory 함수명을 `reload`로 잘못 불렀고 `beginReload`로 수정했다. 다음 파일럿의 정면 M193 ‘shallow’ 기대는 반복 피격으로 소프트가 먼저 약해져 실제 완전 관통이 되어 실패했다. 게임 방호값/RNG를 시험에 맞추지 않았으며 측면 긴 인체 경로에서 실제 체내 정지를 확인하는 사례로 바꿨다. 최종 성공 기록은 검증 JSON의 실행 HTML 해시를 기준으로 하며 초기 실패를 최초 성공으로 표현하지 않는다.

실기기/S24·발열·파일 URL 실행은 미검증이다. 이 환경의 file URL 차단 때문에 오프라인은 네트워크를 끄고 같은 HTML 바이트를 메모리에서 공급해 검증한다. 장기/뼈/혈관 메시, 상처·출혈·둔상/골절·생리·치료, NPC 전투, 실제 다중 파편/파편 질량 변화는 후속이다. 원본 residualKind의 파편 분류는 백커/안정성 메타데이터로 사용하며 여러 파편 탄을 생성하지 않는다. A2의8개 시험 레인 방호력은 계속null/미보정이다. 기존 모든 browser suite를 이번에 재실행했다고 주장하지 않는다.
