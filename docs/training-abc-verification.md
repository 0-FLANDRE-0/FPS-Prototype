**실치수·ply 간격·mm 표지·3D 확률 하한 처리는 완료. 실측 관통/저지 확률 보정은 8개 레인 모두 미보정이다.** `armor:null`은 기존 재질별 방호력으로 계산한다는 뜻이며, 검증된 현실 방호 수치가 아니다. 특히 09번은 장갑 강판이라는 표지/규격을 갖지만 현재 계산은 기존 `steel` 재질이다. 실제 장갑강의 성능을 재현했다고 주장하지 않는다.

변경: `config.js`의 `RANGE_LANES`/`BARRIERS`; `scene.js`의 `rangePlyLabel`, 표지 텍스처와 레인 표지 생성; `ballistics.js`의 `traceShot` 확률 하한. 기존 ballistics/humans/armor Node 테스트의 레인 기하 기대값만 조정했다. 레인 밖 BOXES, aim.js, 레거시 모듈과 원본 src는 동일하다. `residualVelocityScale`은 근거 있는 출구 속도가 없으므로 추가하지 않았다.

### 자료 구분과 목표

- **공식 저작물 / 비공식 미러**: 미 육군 FM 3-06.11, 2002-02-28, 7-2, 인쇄 pp.7-3–7-4. [확인한 PDF](https://www.bits.de/NRANEU/others/amd-us-archive/fm3-06.11(02).pdf). 다운로드 2026-10-10 UTC; PDF SHA-256 `8626bffb99cc9dd1295d1c231bc4f0ef8aad9eed49824d855e4de5a4e541b948`.
- 교범은 얇은 목재/Sheetrock의 낮은 방호, 25m 이내 감소한 관통, 50m 이내 2인치 **단단한 무보강 콘크리트** 등의 경향을 제시한다. Table 7-2의 25–100m, 3/8인치 **연강문**, 초기 1발 조건은 8m 거리의 10mm **장갑 강판**에 전용할 수 없다. 2인치 솔리드 콘크리트도 32mm 벽체 2개/126mm 공극과 다르다.

- **미보정**: 위 자료에는 지정한 8개 규격/거리의 M855 관통 확률과 출구 속도 정량 자료가 없다. 일치하는 비공식 실험 목표도 확보하지 못했다. 각 목표는 빈칸, armor는 null로 유지했다. ±5%p 목표 검사는 적용할 대상 0개다.
- **튜닝 규칙**: −17.9 임계값은 사용자 지시서에 따른 3D 어댑터 규칙이다. 원본 logistic/손실/탄약 수치를 수정하지 않았다.

## C — 걸음 위상과 발디딤 충격

변경: `main.js`의 카메라 보정 `render`, 고정 스텝 `tick`, 카메라 스프링 초기화/`reset`; `settings.js`의 `stepImpact` 기본값/범위; `index.template.html`의 화면 흔들림 옆 슬라이더. `aim.js` 및 물리·탄도는 무수정.

강도0은 기존 sin(time×11.5)/sin(time×5.7) 경로와 진폭을 그대로 쓴다. 켜지면 수직은 sin(2×gaitPhase), 좌우/roll은 sin(gaitPhase)로 한 걸음 사이클에 양발 수직 주기 2회/좌우 주기 1회를 맞췄다. 기존 11.5/5.7을 gaitPhase에 다시 곱하여 다른 고주파를 만드는 방식은 사용하지 않았다. 총의 위상 증가 자체는 원본 그대로다.

π 경계를 넘을 때만 카메라 스프링에 속도 충격을 넣는다. ω30 / ζ.6의 정확한 감쇠해를 1/60초마다 갱신하고 이전/현재 변위를 보간한다. 수직/pitch는 하강 방향, roll은 양발 교대다. 모든 적용은 렌더 카메라 위치/회전에 한정한다. viewYaw/Pitch, 자유조준, 총구, 무기 자세는 이 상태를 읽지 않는다.

**튜닝값**: 100% 초기값·0–150 범위, 순수 최대속도/화면흔들림1/비조준/보행 단일 충격의 연속시간 피크 8mm/.4°/.3°, ω30/ζ.6, 질주1.5/앉기.6/ADS(1−.7ads)은 사용자 지시서 값이다. 속도비와 화면 흔들림 .7 때문에 이번 실제 600틱 보행에서 스프링 축의 관측 최대치는 5.521mm / 0.276° / 0.207°였다. 기존 bob/반동까지 합친 카메라 전체 변위의 최대값이라는 뜻은 아니다.

## 실행·오프라인과 검증 재현

모든 빌드에서 844×390 터치/1280×720 마우스의 부팅·이동·1발 사격·장전·인벤토리·탄약 보존을 확인했다. 오류/외부 요청0. 일반 localhost 스모크 외에 브라우저 네트워크를 비활성화하고 동일한 HTML 바이트만 route.fulfill로 메모리에서 공급하는 오프라인 스모크를 실행했다. JS/모델/텍스처/WASM은 전부 내장되어 추가 요청이 없다. 이 런타임 Chromium은 `file://` 이동에 `ERR_BLOCKED_BY_ADMINISTRATOR`를 반환하므로 **직접 file:// 실행은 미검증**이다. 정책을 우회하지 않았다. **S24 실기기도 미검증**이다.

공식 테스트는 `npm test`, `npm run verify:baseline`이다. `scripts/check-training-lanes.mjs`/`scripts/check-training-abc.mjs`는 외부 작업용 하네스이며 CI의72개 테스트와 구분한다. 별도 QA HTML의 폐쇄 변수 접근/RAF 고정은 배포하지 않는다. 원본 legacy와 aim.js는 기준 커밋 대비 바이트 동일이다. 기존 전체 armor/humans/penetration Playwright suite를 다시 돌린 기록으로 해석하지 않는다.

```sh
CQB_STAGE=C CQB_BASELINE_ROOT=/path/to/baseline-worktree node scripts/check-training-abc.mjs
# QA와 동일 HTML 해시를 확인하고 실제 배포 HTML만 오프라인 조작 재검증
CQB_STAGE=C CQB_SMOKE_ONLY=1 CQB_OFFLINE=1 node scripts/check-training-abc.mjs
```

`CQB_QA_ONLY=1`은 조작 스모크를 생략하고 `debug.json`에 기록한다. `CQB_SMOKE_ONLY=1`은 이전 QA/HTML 해시가 같을 때만 스모크와 합쳐 `browser.json`을 만든다. 실제 file:// 테스트는 `CQB_FILE=1`이며 이 환경에서는 위 정책 오류로 중단됐다. A 레인 하네스는 현재 기본 `/workspace/CQB-HTML-baseline`에서 구 레거시 어댑터를 읽는다. `seed+shotIndex`마다 기존 shotRandom을 새로 만들어 동일 난수 접두사를 각도 비교에 쓴다. A 레인 수치와 B/C의 카메라 초기값은 별개의 종류의 자료다.
