# M6: 장비별 격자·헬멧·리그 벗기·줍기·총 무게

v62(M4c) 위에서 작업한다. 3D는 2D와 분리된 상태다. 2D 원본은 바꾸지 않는다. 바꾼 항목은 대장에 출처/원본/튜닝/사용자 설계값/게임 허용과 `2D 역이식 후보`를 표시한다.

M5(타인 치료)는 아군이 없어 보류하고, M6을 먼저 한다.

## 0. 작은 수정: 한 손 수혈 허용

- v62는 한 손 상태에서 수혈 연결을 거부한다("두 손 필요").
- 사용자 원칙은 "PMC라 모두 자가 처치 가능, 한 손이면 느려질 뿐"이다.
- 한 손 수혈 연결을 허용하고, 기존 한 손 배율과 상한(M4c)을 적용한다.
- 근거 참고: 흉골 골내 주사 등 한 손 접근이 가능한 방식이 있다. 단순화는 게임 허용으로 적는다.

## 1. 병사 모델 메시 구성 (검수 담당이 v62 내장 GLB로 확인함)

`soldier-data` GLB 메시 6개를 확인했다. 작업 전에 같은 내용인지 다시 확인하고 보고한다.

| 메시 | 정점 수 | 내용 | 주 뼈 |
|---|---:|---|---|
| Head | 3903 | 헬멧 껍데기 + 고글 + 헤드셋 + **목 보호대** + 얼굴 일부 | head 3639 / chest 145 / neck 119 |
| material | 255 | 고글 렌즈 | head |
| Vest | 3180 | 방탄복 몸통 + 어깨 보호대 + 사타구니 덮개 + **무릎 보호대** | chest, 팔·다리 |
| Equipment | 3569 | 가슴 탄창 파우치(chest 1409) + 허리 옆·등 뒤 파우치(pelvis 2160) | chest / pelvis |
| Body | 5258 | 군복·피부 | |
| TorsoUnderlayer | 297 | 기존에 작업 AI가 만든 속옷 상의 | chest·pelvis·spine |

**확인된 문제**
- Head의 가장 큰 연결 덩어리(708정점)가 헬멧 껍데기와 목 보호대가 이어진 한 조각이다. 헬멧 부분은 head 뼈, 목 보호대 부분은 chest·neck 뼈 가중치로 깔끔하게 갈린다.
- 방호 데이터에서 목 보호대(`builtInProtection.neckGuard`, 아라미드)는 **6B45 방탄복**에 속한다. 그림(헬멧)과 판정(방탄복)이 어긋난다.
- 헬멧 밑에 머리 윗면이 없다. 헬멧 껍데기가 곧 머리 겉면이다.
- 무릎 보호대가 Vest 메시에 같이 들어 있다.
- 어깨 보호대는 그림에 있지만 6B45 데이터는 `shoulderGuard:false`다. 이번엔 판정을 바꾸지 않고 기록만 한다.

## 2. 메시 분리 (뼈 가중치 기준)

정점별로 가장 큰 가중치 뼈를 기준으로 삼각형을 나눈다. 삼각형 하나의 정점이 갈리면 다수 기준으로 정하고, 경계가 깨져 보이지 않게 처리한다.

| 장비 | 포함 |
|---|---|
| **헬멧** | Head 메시의 head 뼈 부분(목 보호대 제외) + 고글 렌즈(material) + 고글·헤드셋 조각 |
| **방호 리그(6B45)** | Vest 메시(무릎 보호대 제외) + Head 메시의 목 보호대(chest·neck 뼈 부분) + Equipment 메시의 가슴 파우치(chest 뼈 부분) |
| **벨트** | Equipment 메시의 허리 파우치(pelvis 뼈 부분) |
| **몸에 남는 것** | Body, 무릎 보호대, 얼굴 조각(헬멧에 속하지 않는 것) |

- **바라클라바(머리 덮개) 메시를 새로 만든다.** 헬멧을 벗으면 보인다. TorsoUnderlayer처럼 저작하고 출처를 "authored"로 적는다.
- TorsoUnderlayer는 리그를 벗으면 보인다(기존 의도대로).
- 1인칭 자기 머리·헬멧 숨김(v52)은 분리 후에도 유지한다.
- 원본 GLB 파일은 바꾸지 않는다. 런타임에서 나눈다.
- 적 병사도 같은 분리를 쓸 수 있게 공통 함수로 만든다. 이번에 적이 벗는 동작은 없다.

## 3. 장비 슬롯과 격자

### 리그 (6B45, 사용자 설계값)
```
[1×1][1×1][1×1]
[1×2][1×2][1×2][1×2]  [2×2]
```
- 위 1×1 3칸, 아래 1×2 4칸, 오른쪽 2×2 1칸.

### 벨트 (사용자 설계값, 왼쪽부터 순서대로)
```
[1×1][1×2][1×2][1×1]
```

### 배낭
- 지금 가방 6×5를 그대로 배낭으로 쓴다. 모델은 없고 기능만 있다(나중에 모델을 구하면 붙인다).

### 규칙
- 파우치마다 독립 격자다. 아이템이 파우치 두 개에 걸칠 수 없다.
- 1×2 파우치에는 1×2 하나 또는 1×1 두 개가 들어간다.
- 기존 `InventoryUI` 선택·드래그와 M2 컨테이너 소유 구조(`container:` 루트 추적)를 재사용한다. 소유 표기 예: `rig:pouch-3`. 순환·중복 소유 금지 규칙을 그대로 지킨다.
- 헬멧·리그·벨트·배낭은 장착 슬롯 아이템이다.

### 처음 배치 (사용자 확인)

| 자리 | 넣을 것 |
|---|---|
| 리그 1×2 ×4 | M4 탄창 4개 |
| 리그 2×2 | IFAK |
| 리그 1×1 ×3 | 비움 |
| 벨트 1×2 ×2 | AK 탄창 2개 |
| 벨트 1×1 ×2 | 비움 |
| 배낭 | 위생병 파우치, 복부 키트, 탄약 상자, 나머지 |

- 지금 가방·상자에 있는 탄창 수가 이 배치와 다르면 차이를 보고하고, 남는 건 배낭에 넣는다.
- 탄 수, 아이템 수, 총 질량이 v62와 같은지 확인한다(위치만 바뀜).

## 4. 꺼내는 위치에 따른 시간

- **리그·벨트:** 지금처럼 바로 쓴다.
- **배낭:** 배낭에서 아이템을 꺼내거나 넣을 때 열기 시간이 한 번 든다. 크게 차이 나지 않게 한다(사용자 설계값).

  | 모드 | 배낭 열기 |
  |---|---|
  | 게임 | 약 1 s |
  | 리얼리스틱 | 약 2 s |
  | 현실 | 약 3–4 s |

  - 열려 있는 동안 이동·사격은 불가능하다(처치처럼).
  - 닫거나 이동하면 다시 닫힌다.
- **재장전**
  - 리그·벨트 탄창에서만 한다.
  - 자동 장전 순서(기존: 한 발 이상 든 가방 탄창 우선 → 위 행부터 왼쪽)를 "리그 → 벨트, 각 장비 안에서 위 행부터 왼쪽"으로 바꾼다.
  - 배낭 탄창은 재장전에 쓰지 않는다. 리그·벨트로 옮겨야 한다.
- **의료 처치:** 배낭에 든 물품을 쓰면 처치 시작 전에 배낭 열기 시간이 더해진다. 리그 IFAK은 바로 쓴다.

## 5. 헬멧·리그 벗기·입기

- **동작:** 인벤토리 장착 칸에서 [벗기], 또는 [주변]으로 끌기.
- **시간:** 벗기·입기 모두 빠르게(사용자 설계값). 모드별로 수 초 이내(튜닝)다. 처치처럼 손이 묶이고 이동·사격·피격으로 중단된다.
- **벗으면**
  - 2절 메시를 떼서 **물리 물체로 바닥에 떨군다**(v52 총 떨구기 방식). 콜라이더는 근사 박스 또는 볼록 껍질.
  - 그 장비의 방호 판정이 빠진다: 헬멧 → 6B47 헬멧, 리그 → 6B45 소프트·플레이트·목 보호대·사타구니 덮개.
  - 무게가 빠진다(8절).
  - 리그 파우치의 내용물은 리그 안에 그대로 있다. 리그가 바닥에 있는 동안 [주변]에서 그 격자를 열 수 있다.
- **입으면:** 메시와 판정, 무게가 원래대로 붙는다. 방호 상태(플레이트 손상 등)는 아이템에 남아 이어진다.
- 벨트·배낭 벗기는 이번에 하지 않는다.

## 6. 무기·탄창 떨구기·줍기

- **떨구기**
  - 인벤토리에서 무기·탄창을 [주변]으로 끌면 플레이어 앞에 물리 물체로 떨어진다.
  - 장착 중인 무기를 떨구면 기존 무기 해제 규칙(빈손, 전환)을 따른다.
- **모델**
  - 무기는 기존 M4·AK 모델을 쓴다(현재 부착물·광학 반영).
  - 탄창은 무기 모델의 탄창 부분 또는 별도 탄창 메시를 쓴다. 없으면 임시 상자를 쓰고 보고한다.
- **줍기**
  - 반경 약 2 m 안에서 물체 중앙을 바라보면 "줍기 [F] / 터치"가 뜬다. 기존 상호작용 버튼 체계를 재사용한다.
  - 줍기는 빈 자리에 자동으로 넣는다. 리그·벨트를 우선하고(탄창), 없으면 배낭이다. 자리가 없으면 거부한다.
- **[주변] 탭:** 오른쪽 열의 [주변]을 켠다. 반경 약 2 m 안의 바닥 물건(헬멧, 리그, 무기, 탄창)과 기존 탄약 상자가 나온다. 끌어서 장착하거나 넣는다.
- 바닥 물건은 구역을 초기화할 때까지 남는다.
- IFAK·파우치·약 같은 다른 물품 떨구기는 하지 않는다(나중).

## 7. 화면

- **왼쪽 장비 열:** 헬멧, 방호 리그, 벨트, 배낭 슬롯 + 총 2정(M2 배치 유지). 벗은 슬롯은 빈칸으로 표시한다.
- **가운데 열**
  - 리그 → 벨트 → 배낭 격자를 위에서부터 제목과 함께 쌓는다.
  - 배낭 격자는 열기 전에는 닫힌 표시이고, 열면(시간 소요) 조작할 수 있다.
  - 844×390에서는 스크롤한다.
- **D2 HUD 실루엣:** 헬멧·리그를 벗으면 자세 실루엣에 반영한다(선택).
- 1280×720과 844×390에서 잘림 없이.

## 8. 총 무게 연결 (사용자 설계값)

- 실제 장착·휴대 질량의 합을 계산한다: 헬멧, 리그(플레이트 포함), 벨트, 배낭과 모든 내용물, 무기(부착물·탄창·탄), 의료품.
- 장비 질량 값은 기존 방호 데이터(`weightKg` 등)와 M2 제품 사양을 쓰고, 없는 것은 튜닝으로 적는다.
- **D2 연결**
  - 스태미나와 운동 심박의 고정 입력 `equipmentMassKg 13.7`을 이 합계로 바꾼다.
  - 발소리는 무게 4단계(`loadClass`)를 연속 질량 함수로 바꾼다. 기존 4단계 점을 지나게 맞춘다.
- 새 합계와 13.7 kg의 차이를 보고하고, 처음 장비 상태의 달리기 지속·회복·운동 심박 변화를 표로 낸다.
- 리그를 벗으면 가벼워져서 덜 지치는 것이 실제로 나타나야 한다.

## 9. 하지 않는 것

- 적의 장비 벗기, 적 시체 수색
- IFAK·파우치·약 바닥 떨구기
- 벨트·배낭 벗기, 배낭 모델
- 아이템이 총알에 맞는 판정
- 어깨 보호대 판정 변경
- 탄도·관통·방호 식, 의료 식(8절 질량 입력 교체 제외)

## 10. 검증

1. **메시 확인:** 1절 표와 실제 GLB가 같은지 확인한다. 분리 결과(헬멧, 리그, 벨트, 몸)를 앞·옆·뒤 캡처한다. 목 보호대가 리그 쪽에 있는지, 무릎 보호대가 몸에 남는지 본다.
2. **벗기·입기**
   - 헬멧·리그를 벗은 뒤 같은 부위 사격의 방호 결과가 "방호 없음"으로 바뀌는지
   - 다시 입으면 원래대로인지
   - 바라클라바·TorsoUnderlayer가 보이는지
   - 떨어진 물체의 물리
3. **격자:** 리그·벨트 배치가 사용자 설계와 같은지, 파우치 경계 규칙, 처음 배치의 탄·아이템 수와 질량 보존.
4. **재장전:** 리그·벨트에서만 되는지, 배낭 탄창은 안 되는지, 자동 장전 순서.
5. **배낭 열기:** 모드별 시간, 이동 시 닫힘, 배낭 의료품 처치 시 시간 추가.
6. **떨구기·줍기:** 무기·탄창·헬멧·리그의 바라보기 줍기, [주변] 탭, 리그 안 내용물 유지, 자리 없을 때 거부, 복제·분실 없음.
7. **총 무게:** 처음 장비 합계, 리그 벗었을 때 합계, D2 달리기 지속·회복·운동 심박·발소리 크기 전후 비교.
8. **한 손 수혈:** 한 손 상태에서 연결 가능, 배율 적용.
9. **불변:** 장비를 그대로 둔 정지 사격·의료는 v62와 같아야 한다. 질량 연결 때문에 달라지는 운동·발소리 결과는 차이를 표로 낸다.
10. **기존 회귀:** 전체 테스트, 2D baseline 바이트 비교, S0 240조건·684채널, 포인터 잠금, 두 화면 오프라인 실행.
