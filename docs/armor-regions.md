# H01 6B45 메시 기반 소프트아머·플레이트 영역

최신 v10은 6B45 소프트·Br4/15mm 전후면 판·사용자가 지정한6B47의 저지/내구도/인체 저항을 실행한다. [최신 출처/검증](training-protection-verification.md)을 따른다. 아래 형상 및 관측 단계 설명은 **이전 v3 기록**이다. v8에서 전면 목 패널을 원본 `Head`의138삼각형 표면으로 교체하고 헬멧466삼각형을 추가했다. v9에서는24개 관절의 리깅과 함께 방호 sensor도 자세를 따라 움직이며 보호대 상단을 머리 표면 샘플에서 제외했다. 최신 출처/검증은 [머리·목 v8](training-head-neck-verification.md)과 [리깅·경계 수정 v9](training-soldier-rig-verification.md)를 따른다. 당시 v3~v9는 피복 관측 단계였으며 v10에서 계산을 연결했다.

현재 단계는 **피복 형상과 실제 탄 경로의 교차 관측**이다. 사용자 확인에 따라 모델의 방탄복을 **6B45**로 지정했다. 몸통 전후면·측면 연결부·낭심·양쪽 어깨·목 보호구를 소프트아머로 취급한다. 방호 저지·방호층 관통 확률·둔상·내구도 소모·인체 피해는 아직 실행하지 않는다. HUD의 `영역:`은 교차 확인이다.

## 원본 메시의 피복 범위

`h01-6b45-fit-v3`는 원본 GLB의 `Vest` 재질에서 **2,452개 삼각형**을 추출한다. `scripts/training-armor-mesh.mjs`가 원본 SHA-256을 확인하고, 동일 위치의 정점을 연결성 분석에만 사용해 24개 연결 성분을 구분한다. 출력 정점·삼각형·와인딩은 원본 그대로이며, 인접 성분을 잇거나 겨드랑이·목 구멍을 덮는 면을 추가하지 않는다. 원본 GLB와 텍스처는 수정하지 않는다.

원본 `Vest`의 목 보호구는 앞쪽이 열려 있다. 사용자 요청에 따라 전면에 별도 곡면 소프트 보호대 `soft-neck-front`를 추가했다. 이는 원본 추출로 주장하지 않는 **저작한 근사 표면**(`provenance: authored-front-neck-protector`)이다. 폭 160mm·높이 60mm, 중심 Y=1.495m / Z=0.133m, 가로 곡률 반경 140mm이며 상단은 1.525m다. 기존 목 부속과 같은 `6b45_neck` owner·방호값 33을 사용한다. 앞에서 목을 가로막는 표면만 있고, 위쪽 목 구멍을 닫는 캡은 없다. 원본 메시 소프트 8개에 전면 목 1개가 더해진다.

선택한 연결 성분의 첫 원본 삼각형 ID는 다음과 같다. 메시 변경 시 SHA 검사가 빌드를 중단하므로 기존 선택을 새 모델에 조용히 적용하지 않는다.

| 부분 | 첫 삼각형 ID | 삼각형 수 | 취급 |
| --- | --- | --- | --- |
| 몸통과 연결된 목 보호구 | 896 | 1,302 | 위치에 따라 전면/후면/좌우/목 주소 |
| 좌측 연결부 | 1252 | 146 | 조끼 소프트 |
| 우측 연결부 | 1116 | 136 | 조끼 소프트 |
| 전면 하부 연결 패널 | 108 | 112 | 조끼 소프트 |
| 후면 하부 패널 | 900 | 84 | 조끼 소프트 |
| 낭심 보호구 | 0 | 108 | 6B45 낭심 |
| 우측 어깨 보호구 | 220 | 282 | 6B45 어깨 |
| 좌측 어깨 보호구 | 420 | 282 | 6B45 어깨 |

주머니(`Equipment` 재질), 무릎 보호대, 개별 버클·끈 성분은 제외한다. 목과 몸통이 하나의 연결 성분이므로 삼각형 중심의 정규화 높이 1.49m를 목 **주소** 경계로 사용한다. 몸통의 전후면/좌우도 삼각형 중심으로 주소만 나누며, 이 구분이 피복 형상을 바꾸지는 않는다. 이 모델은 skin/animation 없는 정적 A 자세다.

Three.js와 동일한 전체 GLB 월드 경계를 구하고 높이 1.8m·발 높이·XZ 중심을 정규화한다. `armorVertices`, `armorIndices`, `armorPose`를 표시 메시와 Rapier **trimesh 센서**가 공유한다. 소프트아머에 convex hull을 사용하지 않으므로 원래의 구멍·곡면·분리된 부분을 보존한다. 인체 17개 영역은 기존의 근사 센서이며 메시 정밀도가 아니다. 근사 인체 경계가 조끼 안쪽 표면보다 먼저 걸리는 좌표에서는 그 뒤의 소프트 표면을 기록하지 않는다. 향후 자세·인체 경계를 정밀화할 때 따로 검증해야 한다.

## 장비 방호값과 LOS 설계

원본 `armor_6b45_basic_test`와 `PROTECTION_ACCESSORY_PRESETS`에서 값을 읽는다. 조끼 본체 방호값 **32**, 어깨 **32**, 낭심 **33**, 목 **33**이며, 재질은 아라미드다. 본체 최대 내구도 44와 부속별 최대 내구도도 보관하지만 현재 상태를 생성하거나 소모하지 않는다. 몸통·측면은 한 조끼 owner, 목/낭심/어깨 한 쌍은 각각 원본 부속 아이템 owner를 사용하고 좌우 어깨의 위치 주소를 따로 기록한다.

사용자가 선택한 소프트 계산 방향은 **자체 방호값을 기본으로 하되, 정면 대비 경로 비율이 임계값을 초과할 때만 증폭**하는 방식이다. 실제 원단 mm 두께를 요구하지 않는다. 표면 법선과 실제 탄 방향에서 `normalPathRatio = 1 / abs(n·d)`를 관측한다. 정면은 1이며 접선/퇴화 법선은 `null`이다. 임계값·증폭 기울기·최대 배율과 실제 저지 실행은 후속 계산 단계에서 정한다. 원본 6B45 방호 경로에는 이 임계 증폭 규칙이 없으므로, 적용할 때 원본 방호값/관통 계산과 구분되는 새 공간 보정으로 기록해야 한다.

소프트의 `protectionModel:'rating-only'`는 기본 방호값의 출처를 뜻한다. `plannedObliquityRule:'boost-only-above-threshold'`는 확정한 후속 설계이며 현재 활성 계산이 아니다. 소프트 표면 접촉의 `thicknessMm`, `losMm`, `pathLengthM`, `exitDistance`, `exitPoint`, `startsInside`, `completeExit`는 **null**이다. 앞면부터 뒷면까지의 몸통/공기 길이를 아머 두께로 부르지 않는다.

플레이트는 원본 `plate_granit_br5`의 19mm 두께·재질·방호값·ICW 정보를 유지한다. 폭 250mm·높이 300mm·장착 위치와 shooter-cut의 3D 구현은 프로토타입 규격이다. 병사 로컬 +Y는 위, +Z는 정면, +X는 해부학적 왼쪽이다.

| 플레이트 | 중심 X/Y/Z (m) | 폭 × 높이 × 두께 (m) | 회전 |
| --- | --- | --- | --- |
| 전면 | 0 / 1.310 / 0.1425 | 0.250 × 0.300 × 0.019 | 0° |
| 후면 | 0 / 1.335 / −0.1375 | 0.250 × 0.300 × 0.019 | 180° |

전면만 이전보다 25mm 아래로 내렸다. 전면은 6mm, 후면은 11mm 안쪽으로 넣었으며 후면 높이는 유지한다. 양쪽 판을 가로 원통 곡면으로 만들고 전면 반경 800mm, 후면 반경 900mm를 사용한다. 중앙에서 양 가장자리로 들어가는 양은 각각 약 9.8mm / 8.7mm다. 19mm는 두 원통 반경 차이인 명목 법선 두께이고, 삼각형으로 근사한 실제 사선 통과 길이를 기록한다. 폭은 중앙 곡면의 투영 폭이다. 판 안쪽의 빈 공간을 convex hull로 메우지 않는다.

표시와 Rapier 센서는 같은 닫힌 삼각형 메시를 사용한다. LOS는 그 메시의 정점·와인딩을 공유하는 광선/삼각형 교차에서 구하며, 겹친 삼각형 모서리 교차는 합치고 접선 접촉은 제거한다. 내부 시작·다음 인체/장애물 경계의 부분 출구를 지원한다. 곡면 판을 가로로 스쳐 두 번 지날 때 `materialIntervals`에 두 재료 구간을 남기고 `pathLengthM/losMm`는 그 합이다. 두 구간 사이의 공기는 계산하지 않는다. 이때 첫 `point`와 마지막 `exitPoint` 사이 직선 길이는 LOS와 다를 수 있다. 측면 플레이트·헬멧은 이번 프로필에 없다. 판의 두께가 자동으로 방호력을 의미하지 않으며 장애물 저항 공식을 판에 바로 적용하지 않는다.

## 표시와 탄도 관측

설정의 **소프트아머 영역 표시 / 플레이트 영역 표시**로 초록/주황을 각각 켠다. 기본 꺼짐, 저장/복원, 프리셋 보존, 훈련 초기화 시 보존, 설정 초기화 시 꺼짐을 지원한다. 인체 표시와도 독립이다. 설정을 끄더라도 판정 센서는 유지한다.

센서는 이동·기립·총구 차폐와 기존 첫 인체/장애물 접촉에서 제외한다. 실제 공기 구간의 다음 인체·장애물 접촉 또는 사거리 끝까지만 기록한다. 관통 후 불안정·도탄 후 실제 방향과 잔여 탄도를 사용하며 추가 난수·손실은 없다. 첫 인체 이후의 반대편 장비를 기록하지 않는다. 센서만 스친 발은 인체 점수를 추가하지 않는다.

**플레이트가 피복에 걸리면 처리 순서는 판 → 조끼 소프트다.** 실제 원본 조끼의 외측 표면이 판보다 먼저 교차해도 같은 조끼 백커의 판정은 판 뒤로 배치한다. `physicalOrder`는 실제 거리 순서, `protectionOrder`는 이 처리 우선순위이며, 접촉 좌표·거리·법선·LOS는 바꾸지 않는다. HUD와 `armorContacts`는 처리 순서로 정렬한다. 전후면 중앙은 모두 판 → 소프트 → 인체이며 판 바깥은 소프트만이다. 목/낭심/어깨 부속을 조끼 백커로 묶거나 다른 표적의 판을 대신 적용하지 않는다.

소프트의 원본 표면은 **피복 선택용 외형**이며 물리적인 원단 적층·ICW 백커 위치를 측정한 결과가 아니다. 후속 원본 hard/backer 계산은 동일 owner의 피복을 선정해 판 이후 소프트를 계산하고, 외측 표면을 별도의 추가 소프트 층으로 중복 적용하지 않아야 한다.

## 관측 계약과 후속 단계

`CQBTraining.snapshot().armor`는 6B45 프로필, 원본 SHA/선택 성분/삼각형 수, 표시 상태와 **소프트 9개 + 판 2개**의 월드 변환을 제공한다. 대형 정점 배열을 매 프레임 사본에 포함하지 않는다. `lastShot.armorContacts`와 인체 적중 시 `humans.history[].armorContacts`에는 표적/구역/슬롯/원본 아이템/owner, 실제 접촉 거리·좌표·법선·입사각·방향·비행 상태·잔여 탄도와 물리/처리 순서를 기록한다. 소프트는 `geometry:'mesh-surface'`와 기본 방호값·상대 경로 비율, 판은 `geometry:'curved-solid'`와 실제 LOS를 구분한다. 모두 분리된 관측 사본이다.

다음은 실제 피복에서 선정한 장비와 인체 주소를 원본 방호 함수에 넘기는 좁은 adapter다. 원본 `resolveImpact` 전체로 부위를 재추첨하지 않는다. 소프트 임계 증폭·판 LOS 보정은 명시한 새 공간 규칙으로 연결하고, ICW/Stand-Alone 백커와 국부 내구도의 사건/owner 중복 소모를 막는다. 인체 출구·후면 방호 재판정과 의료는 아직 별도 단계다.

## 검증

```sh
npm test
npm run verify:baseline
CQB_BROWSER_EXECUTABLE=/usr/bin/chromium npm run test:training:armor
CQB_TRAINING_FOCUS=offline CQB_BROWSER_EXECUTABLE=/usr/bin/chromium npm run test:training:browser
```

Node는 전면 목 보호대·목 구멍·판의 닫힌 와인딩·앞판만 하향·양 판의 안쪽 이동·곡률/명목 두께·곡면 판의 두 재료 구간과 공기 제외를 확인한다. 또한 모든 추출 삼각형을 원본 GLB 인덱스/정점/정규화와 독립 대조하고, 목 구멍·팔/몸통 사이 빈틈·무릎 제외·부속·좌우·회전·판 LOS와 기존 장애물 난수/잔여 탄도 불변성을 검증한다. 브라우저는 모바일 두 조건과 PC에서 설정 저장과 실제 총구 사격으로 몸통/판 컷/낭심/양 어깨/노출 팔/무릎 제외/전면 목/후면 판/목/측면 연결부를 확인한다. 결과는 `artifacts/armor/checks.json`에 기록한다. 실제 모바일 기기의 성능·발열·파일 URL 실행은 별도 검증 대상이다.
