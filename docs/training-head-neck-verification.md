# 머리·헬멧 분리와 전방 목 보호대 메시 정합 — v8

## 요청과 구현 범위

머리 피격 형상을 메시 위치에 맞춰 개선하고 실제 헬멧 피복을 별도 센서로 분리하는 첫 단계다. 사용자가 함께 요청한 6B45 전방 목 보호대도 원본 표면으로 교체했다. 기존 방탄복 소프트 8구역과 전후면 플레이트는 유지했다. 방호 저지·내구도·둔상·인체 저항·상처·헬멧 도탄은 아직 실행하지 않는다. 기존 플레이트의 Br5/19mm 메타데이터도 유지한다. 사용자가 제안한 Br4 적용은 다음 방호 계산 단계에서 원본 아이템과 규격을 검토한다.

기준은 A2 게임 기능 `066a7d4d3b5bc2a6aad01432b85e343ddb37a560`이다. 이전 버전과 배송 기록은 보존한다.

## 표면 출처와 형상

병사 GLB는 바이트 단위로 그대로다. SHA-256은 `f38f736aa92ca01564cbc3d6526655fc639677eedd2e0b7f939eb4ca3e0d978a`이며 기존 런타임과 같은 1.8m 정규화를 사용한다. `scripts/training-head-mesh.mjs`가 해시와 primitive 구조를 확인하고 결정적으로 생성한다. 원본이 바뀌면 자동 추출을 멈추고 선택 영역을 재검토하게 한다.

|형상|구성|출처와 한계|
|---|---|---|
|머리|닫힌 1,920삼각형, 962정점|얼굴·턱·뒤목 표면 403개 샘플 + 숨은 머리 557개 저작 샘플과 상하 캡|
|헬멧|466삼각형|`Head`의 삼각형 0–465를 변경 없이 사용; 고글·끈·버클 제외|
|전방 목 보호대|138삼각형|`Head`의 실제 보호대 표면을 연결 추출하고 선택한 상단 경계에서 원본 면 위로 절단|
|기존 소프트|2,452삼각형, 8구역|기존 `Vest` 추출과 구역 그대로|
|기존 플레이트|전후면 곡면 2개|위치·규격·LOS·우선순위 그대로|

전방 목 보호대는 `Vest`가 아니라 **`Head` primitive에 있었다**. 이전의 폭160mm/높이60mm 저작 패널을 제거하고 접힌 실제 곡면을 사용한다. 새 보호대 폭은 약226mm, 높이 약132mm다. 표면을 이동하거나 두께를 부풀리지 않았고, 목 구멍을 막는 캡도 추가하지 않았다. 상단의 중앙/측면 높이 경계는 검토 후 저작한 선택 기준이다. 새 삼각형의 모든 정점이 대응 원본 삼각형 위에 있는지 독립 GLB 파서로 확인한다. 전체를 ‘원본 삼각형 그대로’라고 주장하지 않는다.

모델에는 헬멧 아래의 완전한 맨머리가 없다. 얼굴·턱·뒤목을 원본 표면에서 방사형으로 샘플링하고, 숨은 두부는 타원체를 헬멧 안쪽에 맞춰 닫았다. 보호대 천이 머리 표면으로 잘못 포함되지 않도록 제외한다. 숨은 영역의 8mm 여유는 피팅 수치이며 실제 헬멧 두께나 두개골/인체 조직 두께가 아니다. 머리는 원본의 완전한 인체 메시를 복제한 것이 아니다.

머리와 헬멧 각각 표시/물리 센서에 같은 정점과 인덱스를 사용한다. 인체 피격 17구역·8개 의료 저장 부위 키와 이동 캡슐은 유지한다. 눈/코/턱의 높이 구분은 모델 위치에 맞춘 의미 영역이다. 내부 장기·안구·뼈 콜라이더를 구현한 것은 아니다. 눈 하단1.647m, 코 하단1.606m, 얼굴 상단1.684m는 실측 방탄 기준이 아닌 모델 분류 수치다.

헬멧은 청색 독립 표시를 기본 끔으로 추가한다. 소프트는 녹색, 판은 주황색이다. 실제 헬멧 모델명·방호 등급은 미확정이며 `itemId/material/armorValue/thickness/rating`은 null이다. 외관만으로 6B47 또는 특정 등급을 지정하지 않는다. 피복 교차를 기록하지만 탄속·관통·RNG·점수·탄약에 방호 효과를 주지 않는다.

## 검증과 재현

공식 검증:

- `npm test`: 77/77. 신규 5개는 독립 GLB 원본 대응, 목 보호대 정점의 원본 면 일치/열린 경계, 머리 위상 닫힘·와인딩·표면 샘플 출처, 여러 회전의 실제 Rapier 판정, 표시/센서 정합과 피복 기록의 탄도/RNG 비간섭을 검증한다.
- `npm run verify:baseline`: 원본 HTML 3,641,864 bytes, SHA-256 `ff330c641f9720e3a960adfd84ee084ea06f215366e88e7f03e14803a176f90d`, identical.
- `npm run build:training`: 독립 실행 HTML과 메타데이터 생성. `git diff --check` 통과.

별도 외부 검증 `scripts/check-training-head-neck.mjs`:

- 기존 A2와 새 버전 각각 600틱, 실제 발사6회. 총구 위치/방향·카메라·걸음 스프링 기록을 엄격 동등 비교한다. 렌즈70%, 발걸음100%이며 원본 조준·반동·발걸음 구현은 변경하지 않는다.
- 생산 `tick()`/`fire()` 경로로 눈·턱·정수리·헬멧 테두리·전방 목 보호대·목 열린 부분·측면·후면 사격8건. 탄약1발 소비, 탄약 보존, 부위 기록, 피복 기록, 표적 카운트를 대조한다. 헬멧 테두리만 스치면 인체 미적중이며 점수도 오르지 않는다.
- 고정 조준 사례에 한해서 호흡을0으로 하고 실제 총구 위치를 반복 조준한다. 입력/조준 구현은 변경하지 않는다. 원본 디폴트 조작은 별도 생산 HTML 터치/마우스 smoke에서 확인한다.
- 원본/수정 목 정면, 수정 목 측면, 머리 정면/측면/후면/상단 스크린샷. 형상 확인은 직접 카메라로 별도 캡처하고 렌즈를 끈다. 생산 게임의 기본 렌즈는 유지한다.
- 실제 배포 HTML로844×390 터치,1280×720 마우스/키보드의 시작·이동·발사·장전·인벤토리·탄약 보존·설정 저장/리셋·독립 헬멧 토글을 검증한다. 브라우저 네트워크를 끄고 정확히 같은 HTML 바이트를 메모리로 공급한다. 추가 외부 요청0, 페이지/콘솔 오류0.
- 91개 보호 파일은 기준과 바이트 동일하다. 원본 `src/**`/`CQB_Tactical.html`, 자산, 조준/렌즈/반동/탄도/재질 레인/인벤토리/궤적/기존 방호 메시를 포함한다. `main.js`의 설정 처리 앞부분 전체가 동일하므로 발사·tick·render·발걸음 루프도 유지된다.

자료는 `downloads/checks-head-neck/`에 공식 로그·외부 browser/geometry/scope JSON·600틱 원시 기록·8개 발사 기록·비교 화면으로 보관한다. QA HTML, `__CQBTest`와 가변 접근 코드는 다운로드 HTML에 없다. CI도 공식 테스트/원본 baseline/빌드 후 브라우저 검증본의 HTML 해시와 바이트 수를 대조한다.

### 진행 중 발견과 수정

초기 추출의 보호대 천 일부가 머리 측면에 뿔처럼 잡혔다. 원본 면 샘플에서 보호대 경계 부근을 제외하고 최종 형상을 다시 확인했다. 기존 테스트가 상단 광선에 피복0/표시11개를 기대했으나 실제 헬멧이 추가되어 소프트 피복만 검사/표시12개로 갱신했다. 독립 테스트 파서의 선택적 bufferView offset 처리와 헬멧 테두리 시험 좌표도 고쳤다. 이후 공식77개를 모두 재실행했다.

가까운 측면 외부 사격은4회 조준으로 수렴하지 않아 빗나갔다. 정적 Rapier 교차는 정상임을 확인했고 검증 도구에서 회전에 따른 총구 이동을 반영해 최대16회·1mm 오차 기준으로 반복 조준했다. 최종 전체8건이 통과했다. 생산 조준이나 콜라이더를 시험에 맞춰 바꾸지 않았다.

## 출처 분류와 후속 작업

새로 적용한 공식/비공식 실사격 자료나 방탄 등급 보정은 없다. 피복은 원본 시각 메시, 숨은 머리·경계·의미 영역은 저작 피팅 수치, 탄속/관통 값은 기존 게임 모델 계산이다. 8개 레인의 현실 방호값 미보정 상태도 유지한다.

다음 단계는 사용자 제안 Br4 판의 원본 규격 확인 및 판→소프트 방호 저지·내구도, 소프트 기본 방호값+임계 LOS 증폭, 인체 저항/의료 연결, 헬멧 등급 확인 후 방호다. 현재 정적 A-pose 전용이며 애니메이션 추종은 후속이다. S24 실기기와 `file://` 직접 실행은 미검증이다. 이 환경은 이전에 file URL을 정책으로 차단했으므로 오프라인 검증은 동일 바이트 메모리 부트스트랩 범위다.
