# CQB Training — 인벤토리·의료탭 UX 설계 인계서 (A)

> **성격:** 화면 구조·조작 경험을 다른 설계/구현 AI에게 전달하는 **시각적 UX 설계안**. 구현 명령서가 아니다.  
> **기준:** 2026-10-19 대화에서 사용자가 설명한 요구사항. 참조 빌드 `v56` / `CQB-Training.zip`.  
> **대상:** CQB Tactical(2D)을 바탕으로 제작 중인 CQB Training(Three.js + Rapier 기반 3D 바디캠 FPS).  
> **상태 표기:** **[확정]** 사용자 발언으로 정해진 방향 / **[제안]** 검토용 디자인 / **[미정]** 사용자 확인 없이 고정하지 말 것.

---

## 0. 한 문단 인계

사용자는 **Escape from Tarkov식 고밀도 격자 인벤토리**와 **ACE 의료처럼 개별 손상을 고려하는 처치 상호작용**을 원한다. 장비 화면과 의료 화면은 **공통 3열 레이아웃**을 사용한다. 일반 인벤토리의 왼쪽은 장착 장비, 가운데는 장비별 수납공간, 오른쪽은 주변·상자 등 외부 인벤토리다. 의료 화면에서는 왼쪽이 **신체 8부위+실제 상처 위치**, 가운데가 **선택 부위의 개별 상처 목록+처치 정보+생체 상태**, 오른쪽이 **소지·환자·주변 인벤토리**로 바뀐다. IFAK 등 수납 아이템은 **더블 클릭/더블 터치로 독립적인 이동식 소형 창**을 띄우며, 창 속 아이템을 상처로 **드래그해서 놓거나**, 아이템을 **선택한 뒤 상처 위치/상처 목록을 누르는 방식**으로 쓴다. 전투 시야를 포기하고 여는 메뉴이므로 **가로 모바일에서 빽빽해도 세 열을 유지**하며, 화면 대부분을 점유해도 된다.

## 1. 제품 원칙

1. **[확정] 같은 3열 골격의 두 탭**: `장비/인벤토리`와 `의료`가 서로 다른 정보 배치를 같은 틀 안에서 공유.
2. **[확정] 넓고 조밀하게**: 게임 뷰를 가리는 것은 괜찮다. 화면을 거의 전부 사용하고 작은 슬롯/텍스트도 허용. 모바일이라고 자동으로 한 열에 쌓지 말 것.
3. **[확정] 실제 보유 물품을 사용**: 의료탭에는 가상의 '의료 포인트'가 아니라 장착·수납된 물품을 그대로 표시. 비의료 물품도 남기되 의료 용품을 강조.
4. **[확정] 개별 상처와 부위 동시 탐색**: 신체 8부위 색/체력, 피부 상처의 공간 마커, 선택 부위의 상처 목록이 서로 연동.
5. **[확정] 타인 치료 지원 예정**: 치료 대상과 물품의 소유자는 별개. 우측 소스에 `나 / 환자 / 주변(바닥·상자)` 등 선택지가 존재.
6. **[확정] 플로팅 수납창**: 파우치/IFAK 더블 입력으로 작은 독립 창을 연다. 제목 표시줄을 잡아 이동, `X`로 닫기. 배경 메뉴는 계속 조작 가능.
7. **[확정] 의료 물품 사용 방법 두 가지**: `아이템 드래그 → 처치 대상` 및 `아이템 선택 → 처치 대상 선택` 모두 제공.
8. **[확정] 기존 3D 인벤토리 이동·드래그 로직을 재사용**. UX를 위해 별도 의료 드래그 엔진을 만들지 않음.
9. **[확정] 단축키는 향후 확장**. 이번 UI 시안에 단축키 배치/키 번호까지 확정하지 않음.
10. **[제안] 현실 지향+제한적 게임 허용**: 의료탭이 내부 장기를 모두 자동 공개하는 '엑스레이'가 되지 않도록 관찰/진단/디버그 정보 차별화. 표시 정보 정책은 별도 합의 필요.

├─────────────────────┬──────────────────────────┬──────────────────────────────┤
│                     │                          │                              │
│      왼쪽 패널       │         중앙 패널         │          오른쪽 패널          │
│                     │                          │                              │
│                     │                          │                              │

- 상단 탭 전환으로 **수납 상태·선택 대상·열린 팝업 상태를 의도 없이 초기화하지 않음** [제안].
- 우측 소스를 변경해도 **왼쪽 환자와 중앙 선택 상처는 유지** [제안].
- UI 뒤 게임 화면은 거의 안 보여도 됨. 마진과 장식보다 읽을 수 있는 격자 확보가 우선.

## 4. 의료탭 와이어프레임

### 4-1. 넓은 화면: 1280×720 기준 개념

```text
┌──────────────────────────── MEDICAL ──────────────────────────────────────────┐
│ [장비/인벤토리]  [의료 ●]  환자: PLAYER / FRIEND / ENEMY       [닫기 X]        │
├───────────────────────┬───────────────────────────┬───────────────────────────┤
│ 환자 신체              │ 선택 부위 / 상처            │ 실제 보유한 물품            │
│ [전면] [후면]          │ 우측 팔 (HP: 현재/최대)    │ [나] [환자] [주변]         │
│                        │ ┌───────────────────────┐  │ ┌ 전술조끼 ──────────────┐ │
│        O  머리         │ │ #01 상완 전면 / 관통상 │  │ │ □ □ □ □ [IFAK] □      │ │
│        ▣  목           │ │ 출혈: 관찰됨 / 미처치  │  │ └──────────────────────┘ │
│     ▣██▣  가슴         │ ├───────────────────────┤  │ ┌ 벨트 ─────────────────┐ │
│     ·██▣  복부         │ │ #02 전완 외측 / 파편상│  │ │ [지혈대] □ □ □        │ │
│     •  █  ← 상처점     │ │ 처치됨: 드레싱         │  │ └──────────────────────┘ │
│     █   █  다리        │ └───────────────────────┘  │ ┌ 백팩 ─────────────────┐ │
│                        │ 처치 상태 / 추천 후보       │ │ □ [약물] □ □ ...       │ │
│ 부위별 HP 색/표시       │ 경고/관찰 증상              │ └──────────────────────┘ │
│ 선택 부위 강조         │ HR · 혈압 · ECG(표시 조건)  │ 의료 용품만 '강조',        │
│ 상처 마커 직접 선택    │ 치료 중 타이머/진행         │ 비의료 물품도 그대로       │
└───────────────────────┴───────────────────────────┴───────────────────────────┘
```

**왼쪽 — 환자/신체**
- 원본 8부위: `머리 / 목 / 가슴 / 복부 / 왼팔 / 오른팔 / 왼다리 / 오른다리`.
- 각 부위별 HP와 상태 색. 신체 실루엣 위 실제 피부 상처의 위치를 마커로 표시.
- **[제안]** 전면/후면 전환; 측면은 필요할 때 확장. 한 부위에 상처가 많아도 마커를 합쳐버리지는 않음(겹치는 경우 확장 목록으로 선택).
- 부위를 누르면 중앙의 해당 부위 상처 목록으로 이동; 상처 마커를 누르면 중앙에서 그 상처 선택.

**중앙 — 상처/생체/처치**
- 위: 선택 부위 이름·HP·상처 개수. 그 아래 개별 상처 목록(외부 상처/출혈 관찰·처치 여부·경고).
- 상처 선택 시 해당 상처 행과 좌측 마커가 양방향 강조.
- 아래: 현재 적용된 처치, 적용 가능한/추천 후보, 주의사항, 환자 전체 상태(심박수·혈압·ECG 등의 표시 정책은 [미정]).
- 상처끼리 가깝더라도 **실제 상처 데이터는 각각 유지**. 그룹은 한 번에 다룰 수 있는 처치 편의/표시 그룹이지 모든 상처가 하나가 됐다는 뜻이 아님.
- 일부 아이템은 상처 한 점이 아니라 **사지 부위/관류 영역, 특정 상태 또는 몸 전체**에 적용될 수 있으므로 중앙에서 적용 대상으로 안내.

**오른쪽 — 물품 선택/탐색**
- 소스: **나 / 환자 / 주변(바닥·상자)**. 주변 장비/상자를 열었을 때 해당 항목에 접근.
- 선택 소스의 모든 장비별 수납공간을 표시. **의료 물품만 살짝 강조**하되 비의료 물품을 숨기지 않음.
- 상처나 부위를 누르면 적합한 후보 의료템의 강조 수준을 한 단계 더 올림. **'추천'은 UI 후보 표시이며 의학적으로 성공을 보증하지 않음**.
- 상대를 치료 중이라도 `나` 소스로 돌아가 자기 IFAK의 물품을 사용할 수 있음.

### 4-2. 모바일 가로 화면: 844×390 기준 개념

```text
┌─────────────────────── [장비] [의료 ●]  환자:P01  [X] ──────────────────────────┐
│ 신체 (좁고 조밀)    │ 상처·상태 (내부 스크롤)       │ 물품 (장비별 내부 스크롤)    │
│ [앞][뒤]            │ 우측 팔 HP 43/75             │ [나][환자][주변]           │
│   O 머리            │ #01 상완 / 출혈·미처치        │ 전술조끼 ▾                 │
│  ███ 몸통           │ #02 전완 / 파편·드레싱        │ □□[IFAK]□□□                │
│  █ █ 팔             │ ──────────────────────     │ 벨트 ▾                     │
│  █ █ 다리           │ 적용된 처치 / 경고            │ [TQ]□□□□□                  │
│  • 상처 마커        │ HR · BP · ECG*                │ 배낭 ▾                     │
│ 부위 목록/체력       │ *측정값 표시는 조건에 따름    │ □[약물]□□□□                │
└───────────────────────────────────────────────────────────────────────────────┘
```

- **[확정] 모바일에서도 3열 유지**. 각 열은 독립 스크롤 가능; 화면 전체를 차지하는 메뉴 허용.
- **[제안] 열 폭 초기 예시** 좌 25%, 중앙 35%, 우 40%. 고정 치수가 아니라 실제 기기에서 읽기/드래그 테스트 후 조절.
- **[제안] 글자는 짧게**: 모바일에는 `상완 전면 / 관통상 / 출혈`처럼 짧고 정보 밀도 높게. 길게 설명할 땐 선택 행의 세부 펼침 사용.
- **[제안] 플로팅 창을 제목 표시줄로 움직여 필요한 패널을 가리지 않게**. 완전히 화면 바깥에 밀려 X를 누를 수 없게 되는 건 금지.
- 가로 모바일에서 각 열을 세로 한 줄로 쌓는 자동 반응형 변형은 사용자 의도에 맞지 않음.

## 5. IFAK/의료 파우치: 독립 플로팅 창

### 5-1. 열림·이동·닫힘

```text
[우측 전술조끼 슬롯: IFAK(바깥 1칸)]
             ║ 더블 클릭 / 더블 터치
             ▼
   ┌────────────── IFAK ──────────────┐
   │ ≡ 이동용 제목 표시줄         [X] │ ◀ 제목만 드래그하면 창 이동
   ├──────────┬─────────┬─────────────┤
   │지혈거즈  │압박붕대 │  흉부 씰    │
   ├──────────┼─────────┼─────────────┤
   │지혈대    │빈 칸    │  빈 칸      │
   ├──────────┼─────────┼─────────────┤
   │빈 칸     │빈 칸    │  빈 칸      │
   └──────────┴─────────┴─────────────┘
       ║ 물품을 끌거나 선택하면 창 바깥의 의료탭으로 사용 가능
       ▼
   [왼쪽 인체 상처 마커] 또는 [중앙 상처 행 / 부위 / 전신 상태]
```

- **[확정] IFAK 바깥 크기 1칸**. 내부는 독립 격자, **3×3 또는 3×4는 아직 미정**.
- **[확정] 내용물은 '의료 물품'만 수납**. IFAK을 한 번 사용하는 회복 아이템이 아니라 **의료 물품을 담는 실물 파우치**로 취급.
- **[확정] X 닫기**는 창만 닫고 내부 아이템은 그대로 유지.
- **[확정] 창은 다른 위치로 옮길 수 있음**. 일반 모달처럼 뒤의 의료탭 조작을 막지 않음.
- **[제안] 창의 제목 표시줄과 아이템 격자의 제스처 구역을 명확히 구분**. 창 이동 때문에 아이템이 드래그되지 않아야 함.
- **[미정] 여러 파우치 팝업의 동시 오픈 개수, 팝업 좌표 기억, 창 겹침 순서, ESC 닫기 동작.**

### 5-2. 수납공간의 물리적 제약

- **[확정] IFAK 내부는 의료 물품으로 제한**. 
- **[제안] 물품별 허용 크기/부피·파우치별 용량/태그 검증**, 내용물 무게 합산, 수납장비 안의 다른 수납장비 금지(무한 수납/순환 소유 방지).
- **[주의] 바깥 1칸과 안쪽 1칸은 같은 실제 부피 단위가 아님**. 단순 격자 개수만으로 '1칸에 12칸 무한 압축'을 정당화하지 말 것.
- IFAK, 다른 의료 파우치, 일반 수납 컨테이너는 **공통 팝업 UX**를 사용하되 허용 물품/용량은 개별 정의.

## 6. 의료 아이템 사용 동작: 두 방식 동일 결과

### A. 드래그해서 상처에 적용

```text
[IFAK 안의 지혈거즈] ── 끌기 ──▶ [좌측 팔 상처 #01 마커]
                                  또는
                                  [중앙 상처 #01 행]
                            ↓
                   [적용 가능 여부 피드백]
                            ↓
                   [처치 시간/상태 진행]
                            ↓
                  [효과 판정 + 물품 소모]
```

### B. 선택하고 적용

```text
[IFAK 안의 지혈거즈 한 번 누름]
            ↓
[선택됨: 이 아이템이 적용 가능한 대상만 강조]
            ↓
[좌측 상처 마커 / 중앙 상처 목록 누름]
            ↓
[위 A 방식과 동일한 실제 처치 로직]
```

두 방법 모두 **같은 단일 처치 요청 경로**를 호출해야 함. '드래그는 성공하지만 선택은 효과가 다른' 불일치를 금지.

### 적용 대상 유형

| 화면상 적용 대상 | 예시 | 표현 규칙 |
|---|---|---|
| 국소 상처/상처군 | 붕대, 지혈거즈, 지혈 스펀지 등 | 마커/상처 목록에 적용 |
| 사지·영역 | 지혈대, 부목, AAJT 계열 일부 | 상처 한 점만 눌러야 한다고 강제하지 않음. 적절한 적용 위치 안내 |
| 체강 관련 상태 | 흉부 씰, 감압, 복강 출혈 대응 등 | 외부 조작 위치와 실제 생리적 영향 대상 분리 |
| 전신 | 약물, TXA 등 | 환자 전체 선택 가능. 개별 상처를 반드시 선택할 필요 없음 |

위 표는 **처치 UI의 목표 분류**이고, 약물의 구체적인 효과 수치·적응증·금기·성공률까지 확정한 것은 아님.

## 7. 환자와 아이템 소유자를 독립적으로 선택

```text
                     치료 주체: P01
                          │
         ┌────────────────┴────────────────┐
         ▼                                 ▼
   환자 = P01 (자기 자신)           환자 = NPC02 (다른 사람)
         │                                 │
         └─────────── 공통 의료탭 ──────────┘
                          │
             우측 물품 출처 별도 선택
             ┌────────┬────────┬───────────┐
             ▼        ▼        ▼
            나       환자      주변(바닥·상자)
```

- **[확정] 다른 사람도 치료 가능하게 설계**. 다만 치료 대상이 다르다고 의료 물품의 소유자가 자동으로 바뀌지 않음.
- **[제안] 우측 `환자` 인벤토리 접근에는 거리·손 위치·접근 가능 상태 등을 판단**. 현행 구현에 없는 상세 조건은 사용자 결정 후 확정.
- **[미정] 적 NPC의 수색 허용 범위, 의식 유무, 장비 소유권/약탈, 둘 이상의 주변 컨테이너가 있을 때 선택 방식.**

## 8. 강조·상태·피드백 원칙

1. 선택한 부위: 좌측 외곽선/상태 표시 강조, 중앙 해당 목록 스크롤.
2. 선택한 상처: 좌측 해당 마커 + 중앙 해당 행 동시 강조.
3. 의료 용품: 우측 전체 인벤토리 내 미세한 강조. 비의료 물품은 계속 보임.
4. 상처 또는 적용 위치 선택 이후: 호환 가능한 물품을 더 강조; 불가능한 물품은 이유를 확인할 수 있게.
5. 물품을 든 상태: 유효 드롭 위치와 유효하지 않은 위치를 구분. 실패해도 물품 소모 없음.
6. 처치 도중: 사용 도구·대상·진행 상태·중단/완료 여부를 표시 [제안].
7. 실제 효과는 출혈·의식·통증 등의 **기존 게임 의료 모델 결과를 읽어서 표시**. UI만으로 HP를 회복시키거나 내부 출혈을 지워서는 안 됨.
8. **[미정] 환자가 볼 수 없는 내부 장기·혈관의 정확한 손상량과 ECG/혈압을 어떤 장비·검진 절차로 공개할지.** 최종 의료 UI와 개발자 디버그 표시는 구분할 필요가 있음.

## 9. 대표 시나리오: 인계받은 AI가 시연할 행동

**시나리오 1: 같은 팔에 두 상처**  
`의료탭 → 우측 팔 선택 → 중앙 #01과 #02 별도 표시 → #01 선택 → IFAK 팝업 → 지혈거즈를 #01에 드롭 → #02는 여전히 별도 상처로 남음.`

**시나리오 2: 지혈대처럼 넓은 적용 대상**  
`의료탭 → 출혈이 있는 팔 확인 → 우측 벨트/IFAK에서 지혈대 선택 → 사지 적용 위치를 지정 → 관련 출혈원에 반영 여부는 의료 엔진이 결정.`

**시나리오 3: 동료에게 내 물품 사용**  
`근처 동료 상호작용 → 의료탭의 환자=동료 → 우측 출처=나 → 내 IFAK 열기 → 물품 선택 → 동료 상처 선택 → 처치.`

**시나리오 4: 환자 물품 사용**  
`환자=동료 유지 → 우측 출처=환자 → 환자 조끼 속 IFAK 열기 → 물품 선택 → 같은 환자 상처에 적용.`

**시나리오 5: 창 이동**  
`IFAK 더블 터치 → 창이 중앙 상처 목록을 가림 → 창 제목을 끌어 화면 다른 쪽으로 이동 → 배경의 상처 행 조작 → X로 창 닫기(내용물 유지).`

**시나리오 6: 모바일 직접 조작**  
`844×390 가로 → 3열 모두 유지 → 아이템 터치로 선택 → 상처 마커 터치 → 처치 요청. 제목줄 드래그와 아이템 드래그가 혼동되지 않음.`

## 10. 일부러 확정하지 않은 사항

- 파우치별 실제 격자 크기(예: 3×3 / 3×4), 아이템별 크기·중량·용량 및 장비 장착 위치.
- 인벤토리 세 열의 최종 픽셀/비율, 상처 마커 크기, 더블 탭 시간, 폰의 실제 터치 성공률.
- 처치 시간, 취소 시 자원 처리, 성공률, 출혈 억제량, 부작용, 약물 수치 및 회복 속도.
- ECG·혈압 등의 일반 사용자 노출 조건, 정밀 진단 장비, 신체 전면·후면 표시 범위.
- 단축키 번호, 퀵바 슬롯, 인벤토리 열림 중 시뮬레이션 시간 정책과 플레이어 조작 제한.
- 환자 인벤토리 접근 제한, 적 NPC 치료/파밍 정책, 복수 팝업 허용 정책.

**이 문서의 목적은 UX를 전달하는 것이지 위 미정값을 작성 AI가 임의로 고정하게 하는 것이 아니다.**

## 11. 다른 AI에게 전달할 때 함께 알려줄 것

- 기술 사실/기존 코드 연결표는 동봉 **문서 B (`CQB Training B - 의료·인벤토리 기술 참고 인계서.md`)**를 참조.
- `CQB-Training.zip` v56에서 검수. 3D는 2D와 분리, **원본 2D 파일은 절대 수정하지 않음**.
- **설계 검토 단계**이므로 지시서, 소스 패치, 빌드 생성은 사용자가 별도로 요청할 때까지 하지 않음.
- PC `1280×720`, 폰 가로 `844×390` 둘 다 반드시 확인할 UX 기준 화면.
