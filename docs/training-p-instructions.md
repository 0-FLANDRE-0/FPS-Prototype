# CQB Training 지시서 P — 텍스처 경량화·통증 0 원인·5분 의료 타이머

Oct 10, 2026 · @다고쿠

## 개요

medical-skin-v13 위에 쓰러짐 구현 전 준비 작업 3개를 적용한다. P1은 모델 텍스처를 압축해 HTML 용량을 줄이고, P2는 60초 뒤 통증이 0이 되는 원인을 밝히고, P3는 5분 동안의 의료 경과를 기록해 의식불명·사망 시점을 확인한다. P2·P3은 **조사·기록 작업**이며, 의료 계산이나 표적 동작을 바꾸지 않는다(P2의 연결 누락 수정은 예외, 아래 기준).

P1→P2→P3 순서로 독립 커밋하고 최종 빌드 하나로 제출한다.

공통 원칙:

1. **원본 무수정.** `src/**`, 원본 HTML, 원본 모델, v9 리그 GLB, v13 `soldier-skinned.glb`는 바꾸지 않는다. 텍스처 압축본은 별도 파생 파일로 만든다.
2. **판정 불변.** 탄도·방호·피격 메시·의료 계산 결과는 v13과 같아야 한다.
3. **원본 의료 상수·임계값 수정 금지.** 현실과 다르게 보여도 이번에는 보고만 한다.
4. **출처 분리.** 수치마다 원본 / 공식 자료 / 비공식 자료 / 튜닝값을 구분한다.

## P1. 텍스처 경량화

병사·M4 모델의 텍스처를 WebP로 다시 압축한 파생 GLB를 만들어 배포 HTML에 넣는다. 형상·UV·스킨·뼈는 그대로다.

### 현재 구성 (v13 실측)

| 항목 | HTML 내 크기 | 비중 | 텍스처 |
| --- | --- | --- | --- |
| 병사 (soldier-skinned.glb 11.0 MB) | 14.6 MB | 51% | 1024 PNG 4장(장당 1.37\~1.76 MB), 1024 JPEG 4장, 512 JPEG 1장 |
| M4A1 | 7.8 MB | 27% | 1024 PNG 3장(0.80\~1.19 MB), 512 PNG 3장 |
| 코드 전체 | 6.4 MB | 22% | — |

HTML 크기는 base64 때문에 GLB 원본보다 약 1.33배다.

### 변환 규칙

1. 텍스처마다 용도(base color / normal / metallic·roughness / occlusion / emissive)와 알파 사용 여부를 먼저 표로 정리한다.
2. `EXT_texture_webp`로 교체한다. 대상 브라우저(Android Chrome, 데스크톱 Chrome)가 WebP를 지원하므로 PNG 대체본은 넣지 않는다.
3. 품질 초기값(튜닝값): base color·roughness·occlusion은 손실 q85, normal map은 q95. normal에 계단 무늬가 보이면 무손실로 바꾼다. 알파를 쓰는 텍스처는 알파를 유지한다.
4. 해상도는 그대로 둔다. 줄여도 될 후보가 보이면 목록과 근거만 보고한다.
5. 이미 JPEG인 텍스처는 재압축으로 줄어드는 양이 10% 미만이면 원본 JPEG를 유지한다(이중 손실 방지).
6. 변환 스크립트는 결정적이어야 한다. 같은 입력이면 같은 출력 해시.
7. 입력·출력 GLB의 텍스처 외 데이터(accessor, 스킨, 노드, 클립)가 바이트 단위로 같은지 확인한다.

### KTX2는 평가만

KTX2(Basis Universal)는 GPU 메모리까지 줄이지만 별도 디코더 wasm이 필요하다. 이번에는 적용하지 않고, 같은 텍스처로 만든 시험본의 파일 크기·디코더 크기·GPU 메모리 추정만 표로 보고한다. WebP는 파일만 줄이고 GPU 메모리는 그대로라는 점도 같이 적는다.

### 화질 검사

- 텍스처별 원본 대비 PSNR·SSIM을 표로 보고한다. base color SSIM 0.97 미만은 품질을 올려 다시 만든다(기준값은 튜닝값).
- 고정 시점 스크린샷 전후 비교: H01 정면·측면·얼굴 근접, 1인칭 M4 비조준·조준. 렌즈 강도 0과 70 두 가지.
- 최종 HTML 크기와 모델별 크기를 전후 표로 보고한다. 같은 환경에서 부팅 시간도 함께 잔다.

## P2. 통증 0 원인 확인

v13 60초 타이머에서 치료하지 않은 총상의 통증이 0이 됐다. 팔뚝 62.4 → 0, 목 27.8 → 0이다. 같은 상처를 2D 원본에 넣고 돌려 결과가 같은지 확인한다.

### 절차

1. **기록 확장.** 초 단위 timeline에 pain, shock, heartRate, systolicBP, 부위별 통증 요소(원본에 있으면)를 추가한다.
2. **2D 재현.** 원본 `makeUnit`으로 만든 주체에 3D가 만든 것과 같은 `applyDamageEvent` 인자를 넣고, **2D 게임 루프가 매 tick 호출하는 의료 관련 함수 순서 그대로** 60초를 진행한다. 팔뚝·목·몸통 3건.
3. **호출 순서 대조.** 2D 메인 루프가 tick마다 부르는 의료·통증·생리 관련 함수 목록과 3D가 부르는 목록을 표로 나란히 보고한다.
4. **dt 단위 확인.** 2D가 `tickMedical`에 넘기는 dt가 초인지 tick인지 확인한다. 혈액량 경과도 2D·3D를 같이 비교해 dt 오류가 없는지 본다.

### 처리 기준

| 결과 | 처리 |
| --- | --- |
| 2D 원본도 같이 0이 됨 | 수정하지 않는다. 통증을 0으로 만드는 함수·상수와 원본 주석의 의도를 보고한다. 현실성 판단은 사용자 결정으로 남긴다. |
| 3D가 원본 루프의 함수 호출을 빠뜨림 | 빠진 원본 함수를 같은 순서로 추가한다. 다시 돌려 pain·혈액·의식이 2D와 같아지는지 확인한다. |
| dt 단위 불일치 | 3D 연결부의 dt 변환만 고친다. 원본은 그대로. |

- 두 번째·세 번째 경우에만 의료 결과가 바뀐다. 바뀐 수치는 v13 대비 표로 낸다.
- 2D와 3D의 허용 오차는 수치 상 부동소수점 오차 수준이다. 난수를 쓰는 값은 같은 seed일 때 같아야 한다.

## P3. 5분 의료 타이머

치료 없이 5분(300초) 동안 의료 상태를 초 단위로 기록해, 행동불능·의식불명·사망이 언제 생기는지 확인한다. 다음 단계 쓰러짐의 시점이 여기서 정해진다. P2 결과를 반영한 빌드로 실행한다.

### 시나리오

| # | 시나리오 | 비고 |
| --- | --- | --- |
| 1 | 팔뚝 관통 (bare-forearm) | 기존 fixture |
| 2 | 목 관통 (front-neck) | 기존 fixture, junctional bleed |
| 3 | 조끼 뒤 몸통 관통 (soft-through-body-rear) | 기존 fixture |
| 4 | 허벅지 관통 | 새 fixture. A자 자세 정면, 방호구 없는 상부 대퇴 |
| 5 | 팔 → 복부 (arm-first-body) | 기존 fixture, 상처 2개 |

- 모두 production tick을 고정 STEP으로 진행한다. 실시간으로 기다리지 않고 하네스에서 빨리 돌려도 된다.
- 같은 seed로 2회 실행해 결과가 같은지 확인한다.

### 기록 항목 (초 단위)

혈액량(ml와 %), 외부·내부 출혈률, 의식, pain, shock, heartRate, 혈압(수축·이완), breathingEfficiency, lifeStatus, combatEffectiveness, mobility, isDowned·isUnconscious·isDead, downReason·deathReason, 부위별 partDestruction 상태.

CSV와 시나리오별 그래프(혈액량·의식·심박·수축기 혈압)를 다운로드에 넣는다.

### 상태 전환 표

시나리오마다 첫 발생 시각(초)을 표로 보고한다. 300초 안에 없으면 ‘없음’.

- 혈액 손실 15% / 30% / 40% 도달
- isDowned, isUnconscious, isDead 최초 true (그때의 reason 포함)

### 참고 대조표: ATLS 출혈 분류

아래는 미국외과학회 ATLS 교범에 널리 인용되는 출혈 분류다(공식 의학 교육 자료). 판본마다 심박·혈압 기준 표현이 다르므로, 작업자는 사용한 판본을 확인해 보고서에 적는다.

| 분류 | 혈액 손실 | 심박 | 혈압 | 의식 상태 |
| --- | --- | --- | --- | --- |
| I | 15% 미만 | 정상 | 정상 | 약간 불안 |
| II | 15\~30% | 증가 | 정상 | 불안 |
| III | 30\~40% | 뚜렷하게 증가 | 감소 | 혼동 |
| IV | 40% 초과 | 크게 증가 | 크게 감소 | 혼미·의식 저하 |

- 모델이 각 분류 구간에 들어간 시점의 심박·혈압·의식 값을 표로 나란히 적는다.
- 어긋나는 항목은 목록으로만 보고한다. 이번에는 어떤 값도 튜닝하지 않는다.

## 검증 및 제출 조건

### 공통

- `npm test` 전부 통과, baseline identical, 원본 src·원본 모델·v9 GLB·v13 soldier-skinned.glb 바이트 동일.
- 페이지·콘솔 오류 0, 오프라인 외부 요청 0. 844×390 터치 / 1280×720 마우스 스모크.
- v13 대비 600틱·6발의 총구·방향·카메라·걸음 동일.
- v13의 고정 사격 fixture 13개의 탄도·방호·인체 결과 동일. 의료 결과는 P2에서 연결을 고친 경우에만 달라질 수 있고, 달라진 항목을 표로 보고한다.

### P1

1. 모델별 텍스처 표(용도, 알파, 원본·변환 크기, 품질값, PSNR, SSIM).
2. HTML·모델 크기 전후 표와 부팅 시간.
3. 고정 시점 스크린샷 전후 비교(H01 3장, M4 2장 × 렌즈 2종).
4. 텍스처 외 GLB 데이터 바이트 동일 확인, 변환 재실행 시 출력 해시 동일.
5. KTX2 평가 표.

### P2

1. 2D 메인 루프 vs 3D의 tick당 의료 함수 호출 대조표.
2. 팔뚝·목·몸통의 60초 pain·혈액·의식 그래프, 2D와 3D 겹쳐서.
3. 결론: 처리 기준표의 어느 경우인지, 근거 함수·상수·주석.

### P3

1. 5개 시나리오 CSV·그래프·상태 전환 표.
2. ATLS 대조표와 어긋나는 항목 목록.
3. 같은 seed 2회 실행 결과 동일.
4. 허벅지 fixture 스크린샷과 사격 기록.

### 보고 형식

- 변경 파일·함수 목록.
- 빌드 내부 공식 테스트와 외부 검증 스크립트 결과 분리.
- 수치 출처 구분: 원본 / 공식 / 비공식 / 튜닝값.
- 알려진 한계와 S24 실기기 미검증 명시.
