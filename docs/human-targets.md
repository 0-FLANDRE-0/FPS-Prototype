# 정적 병사 표적과 3D 피격 주소

아래는 최초 정적 표적 단계의 계약이다. 최신 v9는24개 관절/4개 클립과 움직이는21개 닫힌 피격 영역을 사용한다. 손·부츠는 원본 정점 hull이며 숨은 몸통은 저작 근사다. 주소는 관절 역변환으로 분류하고8개 의료 키를 유지한다. [최신 리깅·머리/목 경계 검증](training-soldier-rig-verification.md)을 먼저 따른다.

SECTOR 02 입구의 `H01`은 위치 `[17, 0, -4]`, 키 1.8m의 정적 A 자세 표적이다. 기존 3개 표적과 8개 관통 레인은 유지한다. 오른쪽 통로를 통해 들어가 `[17, 0, 3.5]` 부근의 사격선에서 시험한다. 걷기·공격·사망·방호 저지·상처·출혈은 아직 없다. 소프트아머·플레이트의 공간 교차만 추가했으며 [방호 영역 안내](armor-regions.md)를 따른다.

## 모델과 판정

사용자 제공 Soldier Character GLB를 변경 없이 보관한다. 원본의 축 변환을 유지한 채 실행 시 모델 전체 경계의 X/Z 중앙과 발 높이를 정렬하고 높이를 1.8m로 맞춘다. 원본 형상·9개 내장 텍스처를 유지하며 리깅·애니메이션은 없다. 제작자는 Muhamad Mirza Arrafi, CC BY 4.0이며 [크레딧](../apps/training/assets/soldier-credits.json)과 게임 내 출처를 유지한다.

`human-targets.js`의 `BODY_PROFILE`은 모델에 맞춰 작성한 **17개 근사 인체 영역**이다. 머리·목·흉부·복부·골반 5개, 양팔의 상완·전완·손 6개, 양다리의 대퇴·하퇴·발 6개로 구성한다. 팔꿈치·무릎·어깨와 몸통 세부 구역은 해당 영역의 실제 접촉 좌표로 나눈다. 메시 삼각형 자체, 장기·혈관의 해부학적 충돌체는 아니다. 보이는 헬멧·조끼·주머니에는 방호 효과가 없다.

탄도 영역은 Rapier sensor다. 이동·기립 검사에서는 제외하고 탄도 접촉 검사에는 포함한다. 별도의 반지름 0.23m·높이 1.70m 몸통 캡슐이 플레이어와 모델 중심의 겹침을 막으며 탄도에서는 제외된다. 큰 A 자세 경계 상자로 탄도나 이동을 막지 않는다. 다리 사이와 팔/몸통 사이로 지나가는 탄은 인체 적중으로 처리하지 않는다.

설정의 **피격 구역 표시**는 판정에 사용한 같은 프로필과 변환에서 wireframe을 생성한다. 기본은 꺼짐이며 저장·복원을 지원한다. 장애물 너머까지 보이는 훈련용 표시다. 카메라 프리셋은 표시 설정을 보존한다. 훈련 초기화는 적중 기록과 HUD를 지우고 설정을 유지하며, 설정 초기화는 표시를 끈다.

## 주소와 발사 기록 계약

모델 로컬 축은 +Y 위, +Z 정면, +X 병사의 해부학적 왼쪽이다. 부위의 좌우는 카메라나 사수 방향으로 뒤집지 않는다. 입사 측면은 마지막 탄도 구간의 **진행 방향을 반대로 한 벡터**를 병사 로컬 좌표로 변환해 정한다. 관통 후 signed wobble과 도탄 반사 방향이 그대로 들어온다. 상하 입사도 방향 벡터에 남는다.

의료 저장 부위는 원본 `src/medical/foundation.js`의 8개 키 그대로다:

| 저장 부위 `bodyPart` | 주소 `hitPart` | 세부 구역 |
| --- | --- | --- |
| head | head / face | 두개부·얼굴 |
| neck | neck | 정면·후면·측면 목 |
| chest | chest | 상/하부, 중앙/왼쪽/오른쪽 |
| abdomen | abdomen | 상/하복부·옆구리·골반 |
| leftArm / rightArm | left_arm / right_arm | 어깨·상완·팔꿈치·전완·손/손목 |
| leftLeg / rightLeg | left_leg / right_leg | 대퇴·무릎·하퇴·발/발목 |

`fullAddress`는 원본의 `side.region.hitPart.zone.subZone` 구조를 따른다. 위치 선택은 새로운 3D 공간 adapter의 결정형 계산이며 원본의 무작위 부위 선택을 실행하지 않는다. 손/팔꿈치/발 및 흉부 좌우 등 확장 세부 주소는 이후 의료 adapter에서 원본 local-zone/profile에 명시적으로 대응해야 한다. 주소 형식과 8개 저장 부위가 같다고 원본 의료가 이미 연결된 것은 아니다.

확정된 총구 자세 → 기존 장애물 추적 → 첫 인체 접촉에서 종료한다. 조직 내 관통·출구·다중 인체 적중은 아직 계산하지 않는다. 첫 인체 접촉은 한 발에 한 번 적중 점수를 추가한다. 탄약 소비·반동·효과는 기존 확정 발사 사건 한 번을 따른다. 인체에서 장애물 손실 계수나 새 난수를 소비하지 않는다.

`CQBTraining.snapshot().humans.history`는 최대 64개의 분리된 읽기 전용 관측 사본을 제공한다. 총구 발사 번호, 시간, 표적·탄약 ID, 부위 주소, 로컬/월드 접촉 좌표, 월드 법선, 로컬/월드 입사 방향, 일반/관통/도탄 상태와 잔여 관통력·탄속·damage·stability·장애물 횟수·운동에너지를 기록한다. `armorContacts`에는 인체 도달 전 실제 방호 영역 교차를 보관한다. `damage`는 원본 탄의 잔여 입력값이고 실제 HP 손상은 아니다. 누적 횟수는 기록 상한과 독립이다. 스냅샷 수정은 실제 게임을 바꾸지 않는다.

## 다음 의료 단계

이 주소를 입력으로 받는 좁은 adapter부터 만든다. 원본 `resolveImpact`의 첫 무작위 부위 선택을 다시 실행하지 않고, 부위/세부 주소를 고정한 조직·상처 계산 fixture를 검증한 후 출혈·통증·골절·급성 반응을 연결한다. 생리 처리는 고정 tick에 연결하고 치료는 그 상태를 변경한다. 기존 장기·혈관 후보 모델을 3D 장기 형상이나 확정 관통 경로로 설명하지 않는다. 방탄복·플레이트는 별도 단계다.

## 검증

```sh
npm test
npm run verify:baseline
CQB_BROWSER_EXECUTABLE=/usr/bin/chromium npm run test:training:humans
CQB_BROWSER_EXECUTABLE=/usr/bin/chromium npm run test:training:trajectories
CQB_TRAINING_FOCUS=offline CQB_BROWSER_EXECUTABLE=/usr/bin/chromium npm run test:training:browser
```

Node 검증은 17개 실제 Rapier 접촉, 8개 원본 의료 부위, 회전/정면/후면/좌우, 세부 구역, 빗나감, 이동 sensor 제외, 원본 관통·도탄 뒤 인체 접촉, 기록 상한·한 번 집계·초기화를 확인한다. 브라우저 검증은 844×390·640×360 터치 에뮬레이션과 1280×720 PC 실제 입력으로 통로 이동·총구 사격·HUD·설정·기록·초기화를 확인한다. 오프라인 문서에 모델/WASM/텍스처를 모두 내장한다. Android/iPhone 실기기의 발열·메모리·성능과 실제 파일 열기 방식은 별도로 확인해야 한다.
