## 소스 변경

- `optic-data.js`: Vudu·XPS3-0·TA31 공통 정의, 인벤토리 크기/질량/설치 시간/마커/광학 종류/고정 배율. 탄약상자에 XPS3 1×1, ACOG1×2를 추가한다. 기존 Vudu 위치는 유지한다. 인벤토리 설명과 보관 실패 문구는 실제 아이템 크기를 사용해 XPS3도1×1로 표시한다. 모두 M4 전용이고 AK에는 장착하지 않는다.
- `optic-model.js`: 세 모델 로딩과 마운트 가시성/광학 디스패처. 같은 인벤토리 인스턴스를 이동하고 장착/분리 소유권·예약·취소 절차를 유지한다. 모든 광학 장착 시 후방 조준기 조립체를 숨기고 분리 시 복원하며 전방 가늠쇠 모델은 유지한다.
- `aim.js`: 정의별 실제 광학 마커·눈 거리. Vudu90mm, XPS3 173mm(게임 배치값), ACOG38.1mm. ACOG를 기존45mm 하한으로 밀어내지 않도록 광학 하한은 `min(45mm, 공식/설정 눈 거리×.8)`이다. 비장착 M4/AK의 정렬과 장착hip 경로는 유지한다. 초기화할 때 집중 시야 감도 잔류값을1로 복구한다.
- `optic-focus.js`, `settings.js`, `main.js`: **조준경 집중0–100%, 기본100%**. 집중량 `ADS×설정/100×ln(배율)/ln(6)`으로 메인 화각을 좁히고 바디캠 왜곡을 줄인다. 목표 렌즈 영상 높이 비율62%와 보간 곡선은 게임 조정값이다. **배율 조절 시 주변 화면의 화각도 바뀌는 디자인으로 변경했다.** 집중0%, 미장착, XPS3/1×는 기존 경로다. 감도는 이 집중으로 변한 화면 확대율만 보정한다. 배율 자체의 영상 흔들림은 남긴다.
- Vudu 배율은 로그 공간에서 변하며1→6 전체 시간0.4초는 유지한다. Z/X 또는44px −/＋를 누르는 동안 작동하고 이동/사격 터치 소유권과 독립이다. XPS3/ACOG는 고정 배율이므로 버튼을 숨기고 배율 입력을 적용하지 않는다.
- `optic-specs.js`와 공통 PiP 셰이더: 배율별 왜곡·색수차·가장자리5탭 흐림·감광·부드러운 조리개·사출동 그림자·코팅 반사·조명 번짐을 제출본과 같은 수식으로 포팅했다. 한 픽셀당 최대15번의 영상 texture lookup이다. 모두 외관을 위한 튜닝이며 제조사 실측 렌즈 설계가 아니다. 조준 가이드/피격 표시도 같은 왜곡의 근사 역변환을 사용한다.
- `optic-holo.js`: XPS3 창 유리에 무한원 방향 기준68MOA 링/1MOA 점을 그린다. 창 가장자리에서 잘리고 PiP 렌더는 하지 않는다. 사분 눈금/밝기/그레인/반사/번짐은 튜닝이다. 이상적 무한원 콜리메이션이며 실제 EOTECH의 유한거리 시차 오차 재현은 아니다.
- `optic-acog-reticle.js`: 제출된 공식 .223 Chevron 도면 기반 벡터 조준선. TA31 고정4×, 실제 시야7°, 출사동8.13mm, 눈 거리38.1mm를 사용한다. 선/숫자/조명 분할 일부는 도면 비율에서 읽은 값이고 축 감쇠12mm는 게임값이다. SR3 내부 FFP는 기존 공식 각도를 유지하고 영상과 함께 왜곡된다.

XPS3 .227kg, ACOG .42241kg을 기존 반동의 질량 항에만 합산한다. M4 전체 질량은 각각3.297kg/3.49241kg이다. 총구 에너지·탄자 운동량·각도 반동 계수·탄 비행·의료 계산을 바꾸지 않는다. 영점/BDC 정합은 계속 미구현이다. Vudu SR3의100야드/75gr 기준과 ACOG 셰브론100m 표기는 제조사 도식의 조건이며 현재 게임 탄종의 거리 해법으로 검증된 것은 아니다.

원래 패치의 두 주변 문제를 소스에서 보완했다. 초기화 직후 남아 있던 집중 감도를1로 복구하고, XPS3 분리 실패 문구에 실제1×1 크기를 표시한다. Vudu/ACOG는1×2 문구를 유지한다. 기존 탄창 이동 테스트는 추가 아이템으로 채워진 고정 셀 대신 실제 빈 셀을 선택한 후 이동 성공을 확인하도록 고쳤다.

## 제조사·자료값과 저작값

Vudu는 기존 EOTECH31.2/5.09m@100yd 시야와90mm 눈 위치다. XPS3의8oz/3.75in/30×23mm 창과68MOA/1MOA는 제출 키트가 인용한 EOTECH 자료값이다. 구판 XPS 매뉴얼65MOA와 새 도식68MOA 차이를 원문에 기록했다. TA31 [제조사 제품 페이지](https://www.trijicon.com/products/details/ta31-d-100309)와 [Chevron 치수 도면](https://www.trijicon.com/uploads/product-uploads/product-downloads/223_Chevron_Reticle_Dimensions4x32.pdf)을 HTTP200으로 직접 재확인했다. 제품의151.89mm/422.41g/4×32/38.1mm/8.13mm/7°와 도면의 주요 Chevron 각도·100m 영점 기준을 확인했다. 응답 크기/해시/확인값은 검증 JSON의 `newManufacturerFetch`를 따른다. XPS3 수치는 제출 키트의 인용값이며 이번에 독립 재확인한 TA31 자료와 구분한다.

길이/질량/시야·도면 각도 외에 마운트 전후 위치, 설치/분리 시간, XPS 눈 위치, 왜곡/색수차/흐림/감광/반사/번짐·조리개 여유·감도 집중·줌 속도는 게임 조정값이다. 기울어진 기존 기계식 M4 조준 마커 보정은 광학에 겹치지 않는다. 세 광학축은 현재 총열과 평행이며 수치 영점 보정은 없다.

## 재현 가능한 자산 파이프라인

기존 첫 단계 자산 생성기는 그대로 보존했다. 새 `training-side-optics-assets.mjs`가 그 출력에 제출본의 두 번째 텍스처 정책을 적용한다. 근거리 노멀 near-lossless q20, 병사 노멀 lossy q90, MR/AO q90, 기본색q92, WebP60KB 미만과 AK specular 유지다. 해상도/알파/기하/리그/클립을 변경하지 않는다. **무손실 노멀이라는 이전 설명은 현재 전달본에 해당하지 않는다.** 과거 v27 파생 메타데이터는 역사적 첫 단계 기록이고 실제 내장 자산은 `sideOpticsAssets`다.

가까운 노멀의 near-lossless 인코딩은 현재 인코더에서 제출본과 결과가 달랐다. 같은 v27 원본 이미지 해시에는 업로드 ZIP에 들어 있는 승인된 near-lossless 인코딩8장을 재사용한다. 입력/참조 이미지 SHA는 `side-optics-inputs.json`으로 고정한다. 다른 텍스처는 로컬에서 재압축하며 참조 이미지 바이트와 일치한다. 생성 GLB의 JSON/패딩 직렬화 차이는 있어도 모델·클립·모든 이미지 바이트는 제출본과 같다. geometry-only 비교와 알파/PSNR/SSIM을 기록하고 재빌드 캐시는 입력 SHA·정책·인코더로 검증한다. 원본 업로드와 이전 파생본은 덮어쓰지 않는다.

추가 조준경의 상류 원본 GLB 두 개는 제출 ZIP에 없었다. 따라서 제출 HTML에서 추출한 XPS3 1,199,524B/SHA `250020f9846b24fd52e4b5d4622762ffa69447235c777953218ee0e66fb04cd3`, ACOG517,732B/SHA `21b69371de956c389388f9bf69a4f59a92ca62ccf8b8dd4c111a4f5112f71556`를 정본 입력으로 보존하고 빌드마다 그대로 검증/내장한다. 키트에 적힌 축 정규화·제거 부품·원본 치수 대비 변환은 상류 파일과 독립 대조하지 못했다. 현재 파이프라인은 제출된 준비 자산부터 완전히 재빌드된다. 원본 파일부터의 새 자산 준비를 완료했다고 주장하지 않는다.

XPS3: Andruxa-snajper/Sketchfab Standard. ACOG: Mateusz Woliński/CC BY-NC4.0. 기존 모든 크레딧과 제조사 도식 출처를 유지하며 내장 크레딧 및 두 새 `*-credits.json`에 기록했다. 비공개 개인 프로젝트 사용 전제를 유지한다.

## 최종 검증과 배송

- 공식180/180 및 원본 baseline 동일. 미장착 카메라/총구/방향/반동/걸음/스프링600틱6발, 방호·인체·6B47 의료3사례를 v27과 전체 대조한다. 공통 팔72상태/네이티브 장전4×240샘플·탄보존/손 접점·관절 연결도 유지한다.
- 제출본 대 소스 빌드: PC1280×720/터치844×390에서 Vudu1/3/6·집중0·바디캠 렌즈0·XPS3·ACOG의14장면. 카메라/눈/마커/질량을 대조하고 **모든 화면 SSIM1, 픽셀 동일**을 확인했다. PC Vudu1/3/6 세로 FOV65.6620°/42.3758°/30.1493°, ACOG47.5807°다. 모바일의 기본 세로 FOV는 화면비 때문에 별도로 비교했다.
- 일곱 내장 GLB를 검사한다. 기존4,018accessor·모든 리그/클립/원래 비이미지 버퍼 동일, 현재 내장 이미지들은 제출본과 바이트 동일, 새 조준경 정본 GLB는 전체 바이트 동일. 두 ZIP 원문 해시와 게임 HTML의 가변 QA API 부재를 확인한다.
- 세 조준경의 실제 사격/전환 유지/그림자·홀로그램 창 위치 샘플, 실제 키/터치와 최종 HTML 그대로의 오프라인 장착·분리·질량·고정 배율·장거리·탄보존을 검증한다. 결과 및 화면은 `downloads/checks-side-optics-v28*`에 보존한다.

실행 HTML의 정확한 크기/해시/기능 기준·증거 해시는 `downloads/verification-side-optics-v28.json`, 실제 GitHub ZIP 대조는 `downloads/delivery-side-optics-v28.json`을 따른다. `npm run build:training` 뒤 로컬 검증과 `python3 scripts/package-training-local.py --version side-optics-v28`로 재현한다. ZIP은 중복 GLB/전체 화면을 제외하고20MB 미만으로 유지하며 원본/전체 증거는 저장소에 보존한다. GitHub Actions를 실행하지 않는다.

Linux Chromium/SwiftShader의 검증이며 S24/Android/iOS 실제 성능·HalfFloat 지원이 부족한 기기는 미검증이다. 텍스처 해상도가 같으므로 다운로드 감소만큼 GPU 메모리가 줄어드는 것은 아니다. 15tap PiP와 확대된512² 이상의 타깃은 v27보다 렌더 비용이 늘 수 있다. 실물 렌즈군 굴절/초점/디옵터/안구 적응·실제 시차·XPS 밝기/배터리/NV·ACOG 주변광 광섬유·AK 마운트·탄종별 영점/BDC·모바일 지속 FPS는 후속이다. 기존 SwiftShader 바닥표식의 가까운 모델 래스터 흔적과 관리 환경의 직접file:// 제한도 유지한다.
